## 1. 调研：剪映（CapCut / JianYing）

### 1.1 产品定位与设计理念

剪映（国内）/ CapCut（海外）是字节跳动出品的**全民级视频创作工具**，月活数亿。其设计理念：

- **All in AI，All in One**：把"写文案→配音→字幕→剪辑→调色→成片"压缩进一个闭环，AI 贯穿全流程。
- **零门槛 + 专业级**：新手靠模板/AI 一键出片；进阶者有关键帧、蒙版、曲线变速、色轮等专业能力。
- **资源即生产力**：内置免版权音乐/字体/特效/模板，规避法律风险、降低决策成本。
- **多端一致**：移动端、专业版（桌面）、云端能力互通，草稿可续剪。

> 剪映的护城河不是单一功能，而是**「海量素材 + AI 自动化 + 极低操作门槛」的组合体验**。我们正面复刻这一组合，并在「可被 AI 程序化驱动」上做出差异化。

### 1.2 界面布局与交互范式

剪映专业版采用经典 NLE 布局，可归为 **4 大面板 / 7 大区域**：

| 区域 | 职责 | 对齐到 AIcut |
|---|---|---|
| 顶部菜单栏 | 文件/保存/导出/设置 | 顶部命令栏 + 全局菜单 |
| 左侧素材管理区 | 媒体库、音频库、文本工具、特效中心 | 资源面板（素材/资产树） |
| 中部预览窗口 | 实时播放与画布交互（缩放/拖拽） | 播放器 + 画布（Canvas） |
| 右侧参数面板 | 选中对象属性调节（缩放/位置/色彩/动画） | 检查器（Inspector） |
| 底部时间轴 | 无限轨道叠加（视频/音频/文字独立轨） | 多轨时间轴（核心） |
| 快捷工具栏 | 分割(Ctrl+B)/删除/定格/撤销 | 工具栏 + 快捷键 |
| AI 智能入口 | 文本成片、智能抠像、语音转字幕 | AI 面板 + 命令接口 |

**关键交互范式**（需复刻）：拖拽式素材入轨、轨道无限叠加、时间轴 Alt+滚轮精细缩放、Ctrl+C/V 跨工程复制参数、自动踩点（音乐节拍匹配剪辑点）。

### 1.3 功能模块全景

**A. 手动剪辑能力（基础）**
- 多轨时间轴：视频轨、音频轨、文字轨、贴纸轨、特效轨，支持无限叠加与分组
- 剪辑操作：分割、删除、定格、倒放、变速（含**曲线变速**）、旋转、裁剪、镜像
- 画面调节：位置/缩放/透明度/混合模式；**关键帧动画**（移动/缩放/旋转路径）
- 蒙版与混合：线性/圆形/镜面蒙版，实现双重曝光、局部调色
- 画中画：多图层叠加与层级管理
- 转场：3000+ 转场模板（淡入淡出、运镜、遮罩等）
- 滤镜与调色：**色轮/LOG 模式**、一级/二级调色、LUT 叠用
- 文本与字幕：花字、字幕样式、动态文字、打字机/弹入动画

**B. AI 能力（剪映 2026 已上线 14+ 项）**
1. 图文成片 / 文本成片：输入文字 → 自动配画面+配音+字幕（≈30s）
2. 智能包装：已有素材自动加字幕/特效/转场/BGM
3. 自动识别字幕：中文准确率 95%+，支持粤/日/韩等多语种
4. 双语字幕：中英/中日/中韩一键互译生成
5. 文本朗读（AI 配音）：50+ 音色（新闻/搞笑/情感/方言/童声）
6. AI 数字人播报：写实/卡通/3D 形象，口型同步（≈100字/30s）
7. 智能抠像：发丝级精度，支持自定义涂抹扩展
8. AI 调色 / AI 肤色优化：自动亮度/对比/饱和/色温
9. AI 美颜 / 美体：瘦脸/大眼/美白/祛痘、长腿/瘦腰（关键点识别不变形）
10. AI 配乐：按视频类型/时长自动匹配并裁剪 BGM
11. AI 音效推荐：按画面内容推荐转场音效
12. AI 脚本生成：主题 → 分镜脚本（台词/画面/时长）
13. AI 改写：润色/扩写/缩写/换说法
14. 智能降噪：音频降噪提升识别率

### 1.4 技术实现原理与架构

从公开资料与同类专业工具（Premiere/达芬奇）归纳其技术骨架：

- **非线性编辑引擎（NLE）**：基于时间轴的轨道模型，所有操作是可逆的元数据变更（非破坏性编辑），最终由渲染管线物化。
- **合成图（Composite Graph）**：每个轨道/片段是一个节点，按图层顺序、混合模式、变换、特效构成有向无环图（DAG），帧按图求值。
- **解码与代理**：原始素材经 FFmpeg/平台解码器解封装解码；4K/高码率素材用**代理文件（1/2、1/4 分辨率）** 保证实时预览。
- **GPU 实时预览**：预览走 GPU（CUDA/OpenCL/WebGPU/Metal），如 Mercury Playback Engine 多 GPU 协同，实现高分辨率实时回放。
- **渲染导出**：最终成片由渲染管线物化 DAG → 编码（H.264/H.265），支持硬件编码（NVENC/QuickSync/VideoToolbox）与高码率（1080P≥12Mbps、4K≥40Mbps）避免画质损失。
- **AI 集成**：AI 能力以「独立处理节点」形态接入（抠像节点、TTS 节点、字幕识别节点），部分云端、部分本地推理。

> 开源参考 **CapCut-Mate** 采用 `Electron + React`，主进程（Node.js，管系统/安全/文件/下载）+ 预加载脚本（contextBridge 暴露受限 API）+ 渲染进程（React UI）三层架构，IPC 走 `ipcMain.handle` / `ipcRenderer.invoke`。**AIcut 直接复用这一成熟桌面架构作为 GUI 外壳。**

### 1.5 剪映的局限 → 我们的机会点

| 剪映局限 | AIcut 的机会 |
|---|---|
| AI 自动化仅限 App 内"黑盒"按钮，无法被外部 Agent 精确编排 | 原生暴露 **MCP/CLI/REST**，任何 AI（WorkBuddy/Codex/Claude Code）可程序化驱动每一帧 |
| 复杂特效/合成不及 PR/AE | 保留专业底座（关键帧/蒙版/合成图），并把"可脚本化"作为一等公民 |
| 工程文件封闭、跨工具协作弱 | 采用**开放工程格式（JSON/可版本化）**，支持 Agent 直接生成/修改工程 |
| 分辨率/码率默认偏保守 | 明确 1080P 基础、4K 上限，导出参数透明可调 |

## 2. 产品定义：AIcut（桌面版）

### 2.1 一句话定位
> **AIcut = 剪映级体验的桌面视频剪辑器 + 原生 AI 驱动接口**：人能在 GUI 里拖拽成片，AI 能用一句话/一段脚本批量成片。

### 2.2 设计原则
1. **双模同源**：GUI 与 AI 走同一套底层引擎 API，AI 不是"外挂脚本"，而是与手动操作等价的第一公民。
2. **非破坏性 + 可版本化**：工程文件为开放结构化数据，便于 Git 管理、Agent 差分修改、协同审阅。
3. **渐进式专业**：默认零门槛（模板/AI），按需解锁专业能力（关键帧/蒙版/调色）。
4. **规格明确**：长宽比可选、分辨率 1080P 起、4K 封顶，参数透明。
5. **桌面优先**：单一桌面二进制（Electron 打包），AI 接口同进程或本地端口提供，无需独立服务器。

### 2.3 核心差异化（vs 剪映）
- **可被任意 AI Agent 驱动**（MCP 标准协议），而非只能点 App 内按钮。
- **工程即代码**：一份 `project.json` 即可复现/批量生成视频，天然适配 agentic 工作流。
- **Headless 渲染**：无需开界面，桌面进程内即可批量出片（供 Agent/CI 调用）。

└──────────────────────────────────────────────────────────────┘
                           │  统一调用（同一命令总线）
┌──────────────────────────────────────────────────────────────┐
│  编排层 (Orchestration / App Core，Node.js，主进程)             │
│  ├─ 工程管理（打开/保存/版本化 project.json）                    │
│  ├─ 命令总线（Command Bus）：所有操作 = 一条 Command             │
│  ├─ 撤销/重做（Command History）                                │

│  引擎核心 (Engine Core，Rust via napi-rs)                       │
│  ├─ 媒体解码（FFmpeg 绑定：解封装/解码/帧提取/代理生成）          │
│  ├─ 合成图求值（Composite Graph：变换/混合/特效/蒙版）           │
│  ├─ 时间轴模型（多轨、关键帧、片段、转场）                       │
│  ├─ 实时预览（WebGPU 渲染到画布）                               │
│  └─ 渲染导出（DAG → 编码，硬件加速）                            │
└──────────────────────────────────────────────────────────────┘
                           │
┌──────────────────────────────────────────────────────────────┐
│  AI 能力层 (AI Services，可内置/可外接，同桌面进程或本地调用)      │
│  TTS(配音) · ASR(字幕) · 抠像 · 调色 · 数字人 · 脚本生成 · 配乐   │

### 3.2 技术栈选型（推荐 + 备选）

| 层 | 推荐 | 备选 | 取舍理由 |
|---|---|---|---|
| 桌面外壳 | **Electron + React + TypeScript** | Tauri + React | Electron 生态成熟、CapCut-Mate 已验证；Tauri 更轻但 Rust 前端桥接成本高 |
| 引擎核心 | **Rust (napi-rs) 封装 FFmpeg + WebGPU** | C++ 原生模块；纯 Web(OpenReel 路线) | Rust 性能/安全俱佳，napi 与 Node 互通；纯 Web 路线上限受限且 4K 吃紧 |
| 预览渲染 | **WebGPU**（Electron Chromium 已支持） | OpenGL / Skia | WebGPU 跨平台统一、性能好、与 Electron 现成集成 |
| 导出编码 | **FFmpeg（libx264/libx265）+ 硬件编码器** | 平台原生编码器 | FFmpeg 格式最全；NVENC(Windows/Linux)/VideoToolbox(macOS)/QuickSync 做硬件加速 |
| AI 接口 | **MCP Server（官方 SDK） + CLI + 本地 REST/WebSocket** | 仅 REST | MCP 是 Agent 标准协议，WorkBuddy/Codex/Claude Code 原生支持 |
| 状态管理 | Zustand / Redux Toolkit | — | 轻量、适合编辑器复杂状态 |
| 工程格式 | **JSON（可版本化、可 diff）** | 二进制包 | 便于 Agent 直接生成与审阅 |

### 3.3 进程与通信模型（复用 CapCut-Mate 范式）
- **主进程（Node.js）**：拥有引擎核心、文件系统、AI 服务、AI 接口（MCP/CLI/REST）。
- **预加载脚本**：通过 `contextBridge.exposeInMainWorld` 暴露 `window.aicutAPI`（受限、安全）。
- **渲染进程（React）**：仅做 UI，经 `ipcRenderer.invoke` 与 `ipcMain.handle` 通信。
- **安全**：禁用 `nodeIntegration`、启用 `contextIsolation`、渲染进程不直接访问 Node。
- **AI 接口进程模型**：MCP Server 由主进程拉起，监听本地端口（如 `127.0.0.1:18765`），Agent 通过 stdio 或 HTTP 连接；GUI 与 AI 共用同一命令总线，互不干扰。

### 3.4 数据模型（开放工程格式）

工程文件 `project.json`（可版本化、Agent 可生成/修改）：

```jsonc
{
  "schemaVersion": "1.0",
  "meta": { "name": "demo", "createdBy": "gui|agent" },
  "canvas": {                         // 画布/输出规格（§6）
    "aspectRatio": "16:9",
    "width": 1920, "height": 1080,
    "fps": 30, "sampleRate": 48000
  },
  "tracks": [                         // 多轨（视频/音频/文字/贴纸/特效）
    { "id": "v1", "type": "video", "clips": [ /* ... */ ] },
    { "id": "a1", "type": "audio", "clips": [ /* ... */ ] }
  ],
  "assets": [ /* 媒体/字体/特效引用 */ ],
  "templates": [ /* 应用过的模板/包装 */ ],
  "aiJobs": [ /* 已排队的 AI 任务（配音/字幕/抠像…） */ ]
}
```

- **Clip 模型**：`{ id, assetRef, in/out, transform{pos,scale,rotation,opacity}, keyframes[], effects[], mask }`
- **时间轴 = 轨道数组 + 绝对时间轴坐标**，非破坏性（源素材不被修改）。
- **命令（Command）**：所有增删改都序列化为 Command，进历史栈 → 支撑撤销/重做与 AI 重放。

## 5. AI 驱动层设计（重点 · 桌面内）

### 5.1 设计目标
- **同一引擎、两种入口**：GUI 手动操作与 AI 程序化操作都落到 §3.4 的命令总线，二者完全等价、可互相接续。
- **Agent 标准协议**：对外暴露 **MCP**（Model Context Protocol），WorkBuddy / Codex / Claude Code 等任意支持 MCP 的 Agent 都能"即插即用"当插件驱动 AIcut。
- **三种调用形态**：
  1. **MCP Server**（主推）：Agent 通过 MCP 工具调用驱动剪辑/渲染。
  2. **CLI**：`aicut render project.json --out out.mp4`（headless 批量成片）。
  3. **本地 REST/WebSocket**：GUI 运行时，Agent 连接 `127.0.0.1` 本地端口做"实时协作"。

| `add_clip` | 向轨道添加片段 | `assetRef`, `track`, `start`, `duration` |

| `add_text` | 加文字/字幕 | `text`, `style`, `track`, `start` |
| `add_subtitle` | AI 字幕识别 | `clipId`, `lang` |
| `apply_effect` | 转场/滤镜/特效 | `clipId`, `effect`, `params` |

| `render` | 渲染导出 | `out`, `resolution`, `codec`, `crf/bitrate` |
| `query_state` | 查询工程/轨道/资产状态 | — |

> 每个工具返回结构化结果（成功/失败、受影响节点、产物路径），便于 Agent 链式编排与自我纠错。

### 5.3 命令式编排语言（Agent 友好）
除逐条工具调用外，提供**声明式工程脚本**：Agent 直接产出一份 `project.json`（见 §3.4）或精简 DSL，AIcut 解析后一次性构建时间轴并渲染。示例：

```jsonc
// 由 Agent 生成的"图文成片"工程（语义级）
{
  "canvas": { "aspectRatio": "9:16", "width": 1080, "height": 1920, "fps": 30 },
  "script": "用这段文案生成一条 30 秒科技短视频：…（文案）…",
  "voice": "知识男声",
  "music": "科技感",
  "captions": true,
  "out": "out.mp4", "resolution": "1080"
}
```

AIcut 的 **AI Orchestrator** 会把上述语义脚本展开为完整 `project.json`（选素材→配音→字幕→特效→导出），等价于剪映"图文成片"，但**可被 Agent 精确控制每一步**。

### 5.4 与 WorkBuddy / Codex / Claude Code 的集成方式
- **MCP 注册**：`aicut` 作为 MCP Server 注册到 Agent 配置（如 `claude mcp add aicut -- node aicut-mcp-server`）。
- **Skill 文件**：提供 `SKILL.md`（仿 jianying-editor-skill），教 Agent 何时、如何调用 AIcut 工具，含示例与避坑。
- **CLI 兜底**：不支持 MCP 的环境（如某些 Codex 场景）直接用 `aicut` CLI，输出结构化 JSON 供 Agent 解析。
- **本地守护**：GUI 运行时 AIcut 在后台起本地端口，Agent 可"看着界面状态"协作编辑，无需重启。

### 5.5 AI 自动化工作流（对齐剪映）
| 工作流 | 触发 | 步骤（命令总线） |
|---|---|---|
| 图文/文本成片 | Agent 给文案 | 脚本生成 → 选素材 → TTS → 字幕 → 配乐 → 导出 |
| 智能包装 | Agent 给素材 | 识别内容 → 加字幕/转场/特效/BGM |
| 批量口播 | Agent 给 N 条文案 | 循环：TTS→字幕→模板→导出 N 个文件 |
| 多语言发行 | Agent 给成片 | ASR → 翻译 → 双语字幕 → 重导出 |
| 规格重制 | Agent 指令 | `set_aspect_ratio` + 重排 → 多分辨率导出 |

### 5.6 AI 能力清单（内置/外接策略）
- **内置（本地推理，离线可用）**：基础 TTS（本地音色）、ASR（Whisper 类）、智能抠像、AI 调色、降噪。
- **外接（调用云端/第三方 API，需密钥）**：高级音色/数字人、文生视频素材、脚本大模型、翻译。
- **设计原则**：能力以「可插拔 Provider」实现，AIcut 内置轻量 Provider，并允许 Agent/用户在配置中接入自有 API（如 OpenAI/自建模型）。所有 AI 节点统一为合成图中的处理节点。

## 6. 分辨率与长宽比规格（明确需求）

### 6.1 长宽比（可选）
| 比例 | 典型用途 |
|---|---|
| 9:16 | 短视频/竖屏（抖音/Reels/Shorts） |
| 16:9 | 横屏/YouTube/B站 |
| 1:1 | 方形/社媒 |
| 4:3 | 传统/监控 |
| 21:9 | 电影宽幅 |
| 4:5 | Instagram 竖方 |
| 自定义 | 任意 W:H（如 1080×1440） |

> 工程文件记录 `aspectRatio` 与显式 `width/height`；切换比例时画布与导出规格联动，片段按锚点重排（AI 可传入重排策略）。

### 6.2 分辨率阶梯（基础 1080，最高 4K）

| 档位 | 尺寸 | 说明 |
|---|---|---|
| 720P | 1280×720 | 代理/草稿预览可选 |
| **1080P（基础）** | 1920×1080 | 默认输出基准 |
| 2K | 2560×1440 | 进阶 |
| **4K（上限）** | 3840×2160 | 最高渲染目标 |
| 原始 | 源素材原生 | 透传不缩放 |

- 预览默认按 **1/2 或 1/4 代理** 保证流畅；导出时按目标档位物化全分辨率。
- 4K 导出强制走硬件编码（§7），并提示显存/磁盘要求。

### 6.3 渲染管线与硬件编码
- 渲染 = 按时间逐帧求值合成图（Rust 引擎）→ 交给编码器。
- **硬件编码**：Windows/Linux 用 **NVENC**（NVIDIA）或 **QuickSync**（Intel）；macOS 用 **VideoToolbox**。
- 兜底软件编码：libx264 / libx265（无硬件时）。
- 预览用 **WebGPU** 实时合成；导出与预览共用同一合成图定义，保证"所见即所得"。

### 6.4 性能策略
- 代理剪辑（4K 源 → 1/4 代理预览）。
- GPU 合成 + 帧缓存池（常用片段 SSD 预缓存）。
- 后台渲染队列，不阻塞 GUI。
- 大工程延迟加载资产缩略图。

## 7. 渲染与导出

| 参数 | 取值/建议 |
|---|---|
| 编码格式 | H.264（兼容）/ H.265（高压缩，4K 推荐） |
| 容器 | MP4（默认）/ MOV |
| 码率 | 1080P ≥ 12 Mbps；4K ≥ 40 Mbps（关智能压缩，防糊） |
| 帧率 | 工程 fps（默认 30，支持 24/25/50/60） |
| 音频 | AAC 192–320 kbps，48kHz |
| 硬件加速 | NVENC / QuickSync / VideoToolbox，可手动开关 |
| 批量/队列 | 支持多工程/多分辨率排队导出（Agent 批量场景） |
| 水印/导出限制 | 基础版无水印；4K 与高级 AI 可设许可（仿剪映 VIP 思路，待你定） |

> 导出 API 同时服务 GUI 按钮与 AI 的 `render` 工具/CLI，参数一致。
