## 1. 目标与选型

P1 智能抠像要在**不引入 GPL-3.0 / 专利风险**的前提下，对「非绿幕」素材做人像级自动抠像。

| 候选 | 协议 | 结论 |
|---|---|---|
| RVM (Robust Video Matting) | **GPL-3.0** | ❌ 商用传染，放弃 |
| **MODNet** (Xenova/modnet ONNX) | **Apache-2.0** | ✅ 采用 |
| ONNX Runtime | **MIT** | ✅ 推理引擎 |
| RMBG-2 / BiRefNet | 部分 Apache / 未知 | 🕓 留作后续模型选项（UI 已预留 select，暂禁用） |

- 真实权重：`Xenova/modnet` ONNX（**24.68MB**，Apache-2.0），运行时缓存于
  `C:/Users/Administrator/.cache/aicut/models/modnet.onnx`。
- 输入张量 `[1,3,512,512]` float32，ImageNet 归一化；输出**已归一化** matte（无需 sigmoid）。

## 2. 架构（镜像 speech 桥接）

```
前端 KeyingTab.tsx
  └─ window.aicut.keying.generate(assetPath, optsJson)
       └─ preload.ts  aicut.keying.generate
            └─ main.ts  ipcMain 'keying:generate'  → callEngine('keying', --mode matte, --input, --opts)
                 └─ Rust main.rs keying 子命令（把 --mode 并入 opts JSON）
                      └─ src/keying.rs keying_generate()
                           └─ spawn Python: python/keying/bridge.py <input> <optsJSON>
                                └─ core.generate_matte() → MODNet 推理 → 灰度 matte mp4
                                     └─ stdout 单行 JSON {mattePath, duration, width, height, fps, frames, model}
```

桥接与 `python/speech_edit/bridge.py` 同构：仅向 stdout 输出**一行** JSON，其余日志走 stderr；
stdout 重定向保护确保那行 JSON 不被污染。

## 3. 数据契约

### matte 灰度视频约定
- `luma = 抠像值`：**0 = 背景，255 = 前景**（与前端 `applyMatte` / 导出 `geq` 曲线统一）。
- 尺寸 / 帧率 / 时长与源素材一致（ffmpeg rawvideo 管道逐帧推理再编码）。

### KeyingConfig（P1 新增字段，前后端对齐）
```ts
mode?: 'chroma' | 'smart' | 'manual'
model?: 'modnet' | 'rmbg2'          // smart 模式模型；当前仅 modnet 可用
threshold?: number                  // smart：前景判定阈值（默认 0.5）
matteAssetId?: string               // smart：生成的 matte 视频对应的素材 id
edgeSoftness?: number               // 复用为前景边缘柔化带宽
```

## 4. 实现要点

### 4.1 python/keying/core.py
- `_ensure_model()` 优先级：`AICUT_MODNET_MODEL` 环境变量 → `~/.cache/aicut/models/modnet.onnx`
  → 下载（Xenova/modnet 镜像 + GitHub Release 回退）。
- **关键修正**：Xenova/modnet ONNX 输出**已是归一化 matte**，直接 `np.clip(m, 0.0, 1.0)`，
  去掉最初误加的 `sigmoid` —— 否则会把背景 0 错误映射到 0.5（半透明而非全透明）。
- 推理经 ffmpeg rawvideo **管道**逐帧进出，不依赖 cv2；CPU 单线程（`OMP_NUM_THREADS=1`）保稳定。

### 4.2 src/keying.rs（新增）
- `keying_generate(input, opts_json)`：复用 `AICUT_PYTHON_BIN` + `resolve_keying_bridge()`
  （`AICUT_KEYING_BRIDGE` 或 `target/../python/keying/bridge.py`），`.env PYTHONIOENCODING=utf-8`。

### 4.3 src/graph.rs（导出）
- smart 模式不走 YUV chromakey，改为在蒙版之后、opacity/fps 之前把 matte 作为额外 `-i`
  输入，用 `geq` 把 luma 经 `threshold/softness` 曲线映射为 alpha，再 `alphamerge` 叠加到源：
  ```
  [1:v]scale=W:H,geq=lum='clip((lum(X,Y)/255-(thr-half))/(soft),0,1)*255'[mt]
  [src][mt]alphamerge[va]
  ```
- `lib.rs can_keying_via_graph`：smart + 有 `matteAssetId` → 走快速路径；smart 无 matte / manual → false。

### 4.4 前端
- `KeyingTab.tsx` smart 分支：模型 select（modnet 可用 / rmbg2 禁用）、「开始智能抠像」按钮
  → IPC 生成 matte → 注册素材 + 回写 `keying:{mode:'smart', model, threshold, matteAssetId}`；
  生成后展示 threshold / edgeSoftness 滑块（live 系 + pushHistorySnapshot）。
- `keyingRender.applyMatte(source, matteCanvas, threshold, softness)`：
  `alpha = softness<=0 ? (mv>=thr?255:0) : smoothstep(thr-soft/2, thr+soft/2, mv)*255`。
- `WebGPUPreview.tsx` / `PreviewCanvas.tsx` 双路径各维护一个隐藏 matte `<video>`，每帧同步
  `currentTime` + `playbackRate`，调 `applyMatte` 合成带 alpha 预览。

## 5. 验证

### 5.1 单元 / 构建
- `cargo test --lib`：**205 passed**（含 keying 相关回归）。
- `tsc --noEmit` + `vite build`：干净。
- `py_compile python/keying/core.py bridge.py`：通过。

### 5.2 MODNet 真实推理（桥接实跑）
- 合成「绿底 + 肤色人形 blob」测试视频，跑 `aicut-engine keying --mode matte --input ... --opts`
  → 返回合法 JSON，`test_subject_matte.mp4` 生成。
- matte 单帧实测：**背景角点 luma = 0.0（全透明），前景中心 luma ≈ 130（保留，带柔边）**，
  直方图 86% 像素落在 0–63（背景）。✅ 证明阈值曲线与 clip(0,1) 正确。

### 5.3 导出端到端（ffmpeg alphamerge）
- `aicut-engine export smart_subject.json out_subject.mp4` → ✅ 成功。
- 输出单帧实测：**背景角点 avg RGB = 0.0（透明/黑底），前景中心 avg RGB = 83.1（保留）**。✅
  证明智能抠像导出链路打通，绿背景被正确抠透明。

### 5.4 模型输出语义核验（直接诊断）
- 直接加载 `modnet.onnx` 推理：`raw m` min=0 max=1 mean=0.117 median=0 —— 确认**已归一化**。
- 对比：`sigmoid(m)` 会把背景 0→0.5（错误半透明）；`clip(m,0,1)` 背景=0（正确全透明）。
  据此坐实「去掉 sigmoid」的修正正确。

## 6. 已知限制 / 后续

1. **无音轨源导出崩溃（pre-existing）**：`graph.rs` 对 video 轨音频无条件引用 `[0:a]`，
   若源素材无音轨则 ffmpeg 报 `-22` Invalid argument。本次测试视频已补静音音轨绕过。
   属通用导出健壮性缺口（非 P1 专属），建议后续按 `ffprobe` 探测有音轨再挂音频链。
2. **桌面端 In-App 触发未自动点完**：因 Cua Driver 无法选中时间轴 clip、且 `Ctrl+O` 在新构建未
   触发打开对话框，未能在 App 内一键跑完「开始智能抠像」。桥接 / 导出 / 算法均已独立实跑验证；
   建议用户在 App 内手动点一次「开始智能抠像」做最终复核。
3. **rmbg2 / 其他模型**：UI 已预留选择器，待权重与后处理就绪后启用。
4. **GPU 推理**：已落地 ONNX Runtime **CUDA EP**（本机 Blackwell sm_120 实测可用，优先于 DML/CPU）。
   provider 兜底链为 `CUDA → DML → CPU`，CUDA 不可用时回退。见 `python/keying/core.py`。
