# AIcut 蒙版功能设计方案

> 版本：v1.0（待审核）  
> 基于：剪映蒙版交互参考 + AIcut 当前代码现状调研

---

## 1. 背景与目标

### 1.1 现状
- 后端 Rust 已定义 `Mask` 结构体（`shape/params/invert/feather`），`filters.rs` 中 `build_mask_spec` 已能将 `linear`、`circle` 两种蒙版转成 FFmpeg 滤镜串。
- `graph.rs` 的简单导出路径会应用 `clip.masks`。
- 但 `lib.rs::is_simple_project` 在 `masks` 非空时直接返回 `false`，导致带蒙版的工程被强制导向 `ExportPipeline` 逐帧路径，而 `ExportPipeline` 完全未消费 `masks` —— **蒙版在导出时被静默丢弃**。
- 前端 `ClipConfig.masks` 是 `any[]`，全项目没有任何写入真实 mask 对象的代码；PropertiesPanel 没有蒙版 tab；预览管线（WebGPU/HTML5）也只把 `mask` 用于转场，不读 `clip.masks`。

### 1.2 目标
- 让蒙版在**预览**、**导出**两条链路都可用。
- UI 参考剪映，提供直观的形状选择、参数调节、预览区控制点编辑。
- 优先 MVP 覆盖 80% 场景（矩形、圆形、线性、镜面），再逐步扩展复杂形状与手绘。

---

## 2. 蒙版主要用途与典型场景

| 用途 | 典型场景 | 需要形状 |
|---|---|---|
 | 局部显示 / 抠出主体 | 把人物从背景中框出，只保留画面局部 | 矩形、圆形、多边形、手绘 |
| 渐变过渡 | 上下/左右渐变露出下层画面 | 线性渐变（linear） |
| 镜像对称 / 百叶窗 | 创意分屏、镜面倒影 | 镜面渐变（mirror） |
| 文字/LOGO 镂空 | 用文字形状作为窗口看世界 | 文字、矢量形状 |
| 隐私遮挡（反向使用） | 用"反转"把人脸、车牌等区域隐藏 | 任意形状 + invert |
| 描边/阴影装饰 | 给局部画面加边框光或投影，突出主体 | 矩形/圆形 + stroke/shadow |

## 3. 竞品参考（剪映截图分析）

从参考截图可归纳出以下交互与功能：

### 3.1 形状选择栏
- 线性、镜面、圆形、矩形、多边形、星形、爱心、文字、手绘（擦除/还原笔刷）。
- 当前激活形状高亮，可叠加多个蒙版（截图显示"蒙版1 矩形"，暗示可多蒙版）。

### 3.2 几何参数
- **位置**：X、Y
- **旋转**：角度
- **大小**：宽、高（矩形）/ 半径（圆形）
- **羽化**：边缘软化
- **圆角**：仅矩形
- **扩展/收缩**：一键整体放大或缩小蒙版区域

### 3.3 效果增强
- **蒙版描边**：开关、预设样式（单线、发光、偏移、三层、手绘、虚线、降低）、颜色、大小、不透明度、模糊度。
- **蒙版阴影**：开关、颜色、不透明度、模糊度、距离。
- **反转**：把可见区与不可见区互换。

### 3.4 预览区交互
- 在画面上叠加可拖拽的蒙版轮廓（带控制点）。
- 直接拖拽移动、缩放、旋转，比右侧输入框更直观。

## 4. 功能范围：MVP / v2 / Future

### MVP（建议优先实现）
1. **形状**：矩形、圆形、线性渐变、镜面渐变。
2. **基础参数**：位置 X/Y、旋转、大小（宽/高或半径）、羽化、反转。
3. **矩形专属**：圆角。
4. **多蒙版叠加**：一个 clip 可添加 1~N 个 mask，按数组顺序叠加（并集或按 invert 取差集）。
5. **描边与阴影（简化版）**：颜色、宽度/大小、不透明度、模糊度；阴影支持偏移距离。
6. **UI**：PropertiesPanel 新增"蒙版" tab；预览区绘制矩形/圆形轮廓与控制点（可拖拽）。
7. **导出**：让简单工程能走 `graph.rs` 路径并正确输出蒙版；`ExportPipeline` 暂时不支持蒙版（在 UI 给出明确提示）。

### v2
1. **形状扩展**：多边形、星形、爱心、文字轮廓、手绘（SVG path / 位图 mask）。
2. **关键帧**：对 mask 的位置、大小、旋转、羽化做关键帧动画。
3. **预览区完整交互**：任意形状的拖拽、缩放、旋转、顶点编辑。
4. **ExportPipeline 支持蒙版**：在逐帧合成中加入 `apply_masks`（对齐 `docs/调研报告/渲染管线设计.md:578`）。

### Future
1. AI 自动抠像 / 智能选区。
2. 蒙版羽化曲线、亮度/颜色范围键控。
3. 3D 蒙版、透视变形蒙版。

## 5. 数据模型设计

### 5.1 前端类型（TypeScript）

```ts
// gui/src/types.ts
export type MaskShape = 'rect' | 'circle' | 'linear' | 'mirror';

export interface MaskStroke {
  enabled: boolean;
  color: string;      // #rrggbb
  size: number;       // px
  opacity: number;    // 0~1
  blur: number;       // px
  // v2 可扩展 style: 'solid' | 'glow' | 'offset' | 'triple' | 'hand' | 'dashed' | 'dim'
}

export interface MaskShadow {
  enabled: boolean;
  color: string;      // #rrggbb
  opacity: number;    // 0~1
  blur: number;       // px
  distance: number;   // px
  angle: number;      // deg, default 135
}

export interface MaskConfig {
  id: string;
  shape: MaskShape;
  enabled: boolean;
  invert: boolean;
  feather: number;         // px, >= 0
  params: Record<string, number>;
  // 各 shape 的 params 约定：
  // rect:    { x, y, width, height, rotation, roundness }
  // circle:  { x, y, radius }
  // linear:  { x, y, angle, width, feather }   // 渐变带宽度+角度
  // mirror:  { x, y, angle, width, spread }    // 镜面展开角度/宽度
  stroke?: MaskStroke;
  shadow?: MaskShadow;
}

// 修改 ClipConfig
export interface ClipConfig {
  // ... 现有字段 ...
  masks?: MaskConfig[];
  // ...
}
```

### 5.2 后端类型（Rust）

后端 `src/types.rs` 已存在：

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Mask {
    pub shape: String,
    #[serde(default)]
    pub params: HashMap<String, f64>,
    #[serde(default)]
    pub invert: bool,
    #[serde(default)]
    pub feather: f64,
}
```

建议扩展为与前端对齐的完整结构（保持向后兼容，新增字段带 `#[serde(default)]`）：

```rust
#[derive(Debug, Clone, Serialize, Deserialize, Default)]
pub struct MaskStroke {
    pub enabled: bool,
    pub color: String,     // "#rrggbb"
    pub size: f64,
    pub opacity: f64,
    pub blur: f64,
}

#[derive(Debug, Clone, Serialize, Deserialize, Default)]
pub struct MaskShadow {
    pub enabled: bool,
    pub color: String,
    pub opacity: f64,
    pub blur: f64,
    pub distance: f64,
    pub angle: f64,
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct Mask {
    pub shape: String,
    #[serde(default)]
    pub params: HashMap<String, f64>,
    #[serde(default)]
    pub invert: bool,
    #[serde(default)]
    pub feather: f64,
    #[serde(default)]
    pub stroke: MaskStroke,
    #[serde(default)]
    pub shadow: MaskShadow,
}
```

### 5.3 序列化兼容性
- 前端 `MaskConfig` 与后端 `Mask` 字段名保持一致，`params` 里的 key 统一采用 camelCase（如 `roundness`），方便两端共用约定。
- 旧工程没有 `masks` 字段或 `masks: []` 时保持原行为。

## 6. UI/UX 设计

### 6.1 PropertiesPanel 新增"蒙版" Tab

在 `PropertiesPanel.tsx` 的 `TABS` 数组中加入 `{ key: 'mask', label: '蒙版' }`，并渲染新的 `MaskTab` 组件。

`MaskTab` 内部结构（从上到下）：

1. **蒙版列表**
   - 每个 mask 一行：开关复选框 + 形状图标 + 简短参数 + "删除"按钮。
   - 列表底部有 "+ 添加蒙版" 按钮。
2. **形状选择栏**
   - 一排图标按钮：矩形、圆形、线性、镜面（MVP）。
   - 当前选中的形状高亮。
3. **几何参数**
   - 位置 X、Y（可输入数字，也可点"重置到中心"）。
   - 旋转（-180°~180°）。
   - 大小：宽/高（矩形）或半径（圆形）；线性/镜面用"宽度"+"角度"。
   - 羽化（0~200 px）。
   - 圆角（矩形专属，0~100%）。
   - 「反转」开关。
4. **扩展/收缩**（可选，MVP 可后移）
   - 一键按百分比整体缩放蒙版区域。
5. **描边**
   - 开关 + 颜色 + 大小 + 不透明度 + 模糊。
   - MVP 只做纯色描边；v2 加预设样式。
6. **阴影**
   - 开关 + 颜色 + 不透明度 + 模糊 + 距离 + 角度。

### 6.2 预览区覆盖层

在 `PreviewCanvas.tsx` / `WebGPUPreview.tsx` 中，当 clip 被选中且 activeTab 为 `mask` 时：

- 在画面上绘制当前 mask 的 2D 轮廓（矩形画虚线边框+四角控制点，圆形画中心点+半径控制点）。
- 鼠标悬停在控制点上变抓手/缩放光标。
- 拖拽行为：
  - 边框内拖拽 → 移动位置（更新 `params.x/y`）。
  - 四角/四边控制点 → 等比/自由缩放（更新 `params.width/height` 或 `radius`）。
  - 旋转手柄 → 旋转（更新 `params.rotation`）。
- 非编辑态（activeTab 不是 mask）不显示轮廓，避免干扰预览。

### 6.3 时间轴提示

- 带 mask 的 clip 在时间轴缩略图右上角显示一个小"mask"图标，提示用户该片段有蒙版。

## 7. 渲染与导出实现路径

### 7.1 预览渲染

#### WebGPU 路径
当前 `WebGPUPreview.tsx` 的 fragment shader 已预留 `mask`/`mask2` uniform，但只用于转场。建议改为：

1. 为每个 clip 新增一个 **mask alpha 纹理**（或在现有离屏 pass 中生成）。
2. 把当前 clip 的所有 `masks` 依次绘制到该纹理：
   - 矩形 / 圆形：用几何 + 高斯/线性羽化生成 alpha。
   - 线性 / 镜面：用渐变 shader 生成 alpha。
3. 在 Over 合成前，fragment shader 采样 mask alpha，乘以片段颜色 alpha。
4. 描边与阴影：在 mask alpha 纹理生成阶段一并绘制（expanding mask + blur）。

**插入点**：在现有 `transform` uniform 上传之后、`Over` 合成之前；与设计文档 `渲染管线设计.md:578` 的 `apply_masks(transformed, &clip.masks)` 位置一致。

#### HTML5 回退路径
- 矩形 / 圆形：用 CSS `clip-path` + `mask-image` 或 SVG `<mask>`。
- 线性 / 镜面：用 CSS `mask-image: linear-gradient(...)`。
- 描边/阴影：用 CSS `filter: drop-shadow(...)` 或 SVG 滤镜。
- 多 mask：用 SVG `<mask>` 组合多个 shape，最灵活。

### 7.2 导出渲染

当前存在两条导出路径，需要分别处理：

#### 路径 A：`graph.rs`（FFmpeg 命令路径）
- 已在 `filters.rs:361-393` 实现 `build_mask_spec`：`linear` 用 `colorchannelmixer` 调 alpha，`circle` 用 `geq` 表达式。
- MVP 需要扩展 `build_mask_spec` 支持 `rect`：
  - 用 `geq` 表达式判断像素是否在旋转后的矩形内，再叠羽化。
  - 或用 `crop` + `geq` 组合实现圆角矩形 mask。
- `graph.rs` 的 `build_video_chain` 已调用 `build_mask_spec`，所以只要 `is_simple_project` 允许，mask 就能导出。

#### 路径 B：`ExportPipeline`（完整 Rust 逐帧路径）
- 当前不消费 `masks`，这是蒙版导出被静默丢弃的主因。
- 推荐在 v2 实现：在逐帧合成的 `apply_transform` 之后、`apply_filters` 之前，加入 `apply_masks(frame, &clip.masks)`。
- 实现方式可选：
  1. **CPU rasterization**：用 `tiny-skia` 或 `raqote` 把 masks 绘制成灰度图，再与帧 alpha 相乘。实现简单、跨平台，但大分辨率慢。
  2. **GPU compute**：如果 `ExportPipeline` 已经在 GPU 上处理帧，复用 WebGPU 的 mask 纹理生成逻辑，效率最高。
  3. **FFmpeg 滤镜链**：把整个 clip 的 masks 转成 filter_complex 链，走 FFmpeg 硬件加速；适合简单形状组合，复杂形状受限。

### 7.3 导出路径选择的关键决策

当前 `is_simple_project` 因 masks 非空返回 false。建议：

- **MVP**：新增一个 `can_use_graph_path(project)` 判断，当工程只包含单视频轨、无复杂转场/多轨/特效，且 masks 都是 `rect/circle/linear` 时，走 `graph.rs` 路径。
- **v2**：在 `ExportPipeline` 实现 `apply_masks` 后，可取消该限制，让任意工程都能带 mask 导出。

## 8. 关键决策与风险

### 决策 1：是否支持"多 mask 叠加"？
- **建议**：MVP 支持多 mask，但叠加模式只提供"并集"（多个 mask 的可见区合并）。
- **原因**：满足 80% 需求（如同时扣出两个人像），避免引入复杂的布尔运算 UI。
- **风险**：导出时 `graph.rs` 路径需要把多个 mask 串成多个 FFmpeg 滤镜，要确保羽化/反转正确叠加。

### 决策 2：预览区 mask 轮廓是否支持旋转后的矩形？
- **建议**：支持。
- **原因**：剪映参考图中矩形可旋转；后端 `rect` mask 的 `params` 也预留了 `rotation`。
- **风险**：控制点拖拽的旋转/缩放数学需要仔细处理（用 2D 变换矩阵）。

### 决策 3：描边/阴影是否进 MVP？
- **建议**：描边/阴影进 MVP，但只做纯色+模糊，不做复杂预设样式。
- **原因**：截图中描边/阴影是默认展开的常用功能；实现上可在 mask alpha 生成阶段用 expand+blur 完成。
- **风险**：WebGPU 路径需要额外一次 blur pass，可能影响预览性能（大分辨率需注意）。

### 决策 4：手绘蒙版是否进 MVP？
- **建议**：不进 MVP，放 v2。
- **原因**：需要笔刷交互、undo、位图 mask 存储、高性能 rasterization，开发量较大。

### 主要风险
1. **导出路径分裂**：MVP 用 graph.rs 只能覆盖简单工程；用户若给多轨复杂工程加 mask，导出会丢失。必须在 UI 明确提示或在导出前校验。
2. **WebGPU 与 HTML5 预览不一致**：某些 mask 效果（如复杂描边）在 HTML5 回退下可能降级，需要定义清晰的降级策略。
3. **性能**：多 mask + 羽化 + 描边 + 阴影，预览时每帧可能多次 render pass。建议对 mask alpha 纹理做缓存，只在 mask 参数变化时重绘。
4. **跨平台路径差异**：Windows 上 `graph.rs` 与 `ExportPipeline` 行为需要一致测试。

## 9. 实现里程碑

### 里程碑 1：数据模型 + 后端 FFmpeg rect mask（1~2 天）
- 前端 `MaskConfig` 类型落地，`ClipConfig.masks` 改为 `MaskConfig[]`。
- 后端 `Mask` 结构体扩展 `stroke/shadow`（带 default 兼容旧工程）。
- `filters.rs` 扩展 `build_mask_spec` 支持 `rect`。
- 新增 `can_use_graph_path` 判断，让简单 mask 工程走 `graph.rs` 导出。

### 里程碑 2：前端 UI + 预览区轮廓（2~3 天）
- PropertiesPanel 新增"蒙版" tab，`MaskTab` 组件。
- 预览区绘制矩形/圆形轮廓与控制点，支持拖拽移动/缩放/旋转。
- 时间轴 clip 带 mask 小图标。

### 里程碑 3：预览合成（2~3 天）
- WebGPU：在 per-clip pass 中读取 `clip.masks` 生成 mask alpha 并应用。
- HTML5：用 SVG `<mask>` 或 CSS `mask-image` 实现回退。
- 描边/阴影在预览中生效。

### 里程碑 4：导出兜底 + v2 规划（1~2 天）
- 导出前检测：复杂工程带 mask 时给出明确提示。
- 端到端测试 rect/circle/linear/mirror 的预览与导出一致性。
- 设计 `ExportPipeline::apply_masks` 接口，留作 v2。
