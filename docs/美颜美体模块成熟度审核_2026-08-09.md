## 2. 关键发现（按严重度）

### #A【高】皮肤遮罩生成的契约错配 —— 默认美颜皮肤效果可能完全不生效

**代码链（实测追踪）：**
- `BeautyTab.runGenerate` 发送的 opts 仅为 `{ smoothing, whitening, clarity, skinTone, fps, output }`，**不含 `model`，不含 `mode`**。
- `gui/electron/main.ts:350` `beauty:generateMask` → `callEngine('beauty', ...)` 原样透传 → `src/main.rs:286` `beauty` 子命令 → `beauty_generate` → `python/beauty/bridge.py`。
- `bridge.py`：无 `mode` → 默认走 `generate_skin_mask`；opts 无 `model` → `core.py:321` `model_path = None` → **分支 B（阈値法）**，仅返回 `{"maskPath": ...}`。

**契约断点：** 前端 `runGenerate` 的返回解析**只读** `result.faceMaskPath / neckMaskPath / armMaskPath`（多区域解析路径的字段），
而分支 B 根本不产出这三个字段 → 三者均 `undefined` → `mkAsset` 全部返回 `undefined` →
`faceMaskAssetId/neckMaskAssetId/armMaskAssetId` 全空，且 `maskAssetId` 也未回退 `result.maskPath`。

**后果（导出 + 预览两侧）：**
- 导出：`graph.rs:387 collect_beauty_region_masks` 因无 mask 资产返回空 → `if !beauty_masks.is_empty()` 为假 → **整个美颜块（含 `build_beauty_spec` 的 bilateral/eq/unsharp/lutrgb）被跳过** → 美颜无效。
- 预览：`resolveBeautyMaskRefs` 同样拿不到任何 mask → `applyBeautyMulti` 提前返回 → 预览无美颜。
- 即：用户点「生成多区域遮罩」后，UI 仍显示「尚未生成」，且磨皮/美白/清晰/肤色在成片里一个都不生效。

**修复方向（二选一，建议先做 1）：**
1. 前端在 `face/neck/arm` 路径全空时，回退 `result.maskPath → faceMaskAssetId`（或 `maskAssetId`），让阈値法皮肤美颜立即可用。
2. 前端默认发 `mode:"parse"` + 解析模型路径（需先有生产级 `parsing.onnx`，见 #B）。
**严重度：高**——核心美颜皮肤功能的默认路径被此 bug 卡死，建议优先修。

---

#### ✅ #A 已修复（2026-08-09）

**改动文件**：`gui/src/components/panels/BeautyTab.tsx`（`runGenerate`）。

1. 返回解析新增 `maskPath` 字段：`const result = (res.data ?? {}) as { ...; maskPath?: string; ... }`。
2. 注册阈値法单区域 mask 资产：`const singleId = mkAsset(result.maskPath)`。
3. 回退写入 `maskAssetId`（按 face→neck→arm→single→旧值 优先级）：
   `maskAssetId: faceId ?? neckId ?? armId ?? singleId ?? beauty.maskAssetId`。
4. 回调兼容：`faceMaskAssetId/neckMaskAssetId/armMaskAssetId` 仅在多区域解析路径有值时覆盖，否则保留旧值。
5. 同时显式发送 `mode: 'mask'`（此前缺省依赖 bridge 默认，现显式声明，意图更清晰、避免未来默认值漂移）。

**验证**：
- 前端 `tsc --noEmit -p tsconfig.json` 通过（TSC_EXIT=0）。
- 后端契约实证：直接跑 `target/debug/aicut-engine.exe beauty --input <clip> --opts '{"mode":"mask",...}'`，
  返回 `{"fps":10.0,"frames":10,"height":270,"maskPath":"...small_skin_mask.mp4","mode":"mask","model":"beauty_mask","skinCoverage":0.0078,"width":480}`（含 `maskPath`）。
- 修复前该 `maskPath` 被前端忽略（只读 face/neck/arm 三字段）→ 所有 mask 资产 id 为 `undefined` → 美颜皮肤被跳过；
  修复后 `maskAssetId` 指向 `maskPath` 资产 → 导出侧 `collect_beauty_region_masks`（graph.rs 回退 `mask_asset_id`）与预览侧 `resolveBeautyMaskRefs`（beautyRender.ts 回退 `maskAssetId`）均能取到 mask → 磨皮/美白/清晰/肤色在默认路径下生效。

**剩余限制（非 #A 范畴）**：阈値法皮肤检测依赖「单人主脸 + 背景非同色」假设；多区域语义分割（P1）与瘦脸/大眼（P2）仍受 #B 未训练模型约束，需先采集 ≥5K 自有标注训练。

### #B【高】解析模型(P1) / 关键点模型(P2) 权重是 bootstrap/smoke，非生产

- `python/beauty/models/README.md` 明确：`parsing.onnx`、`landmark.onnx` 由 `--smoke` 合成几何数据训练，
  仅用于「验证管线可跑通」；**生产权重必须由 ≥5K 张自有合规标注图 CUDA 训练**，而该数据集**尚未采集**。
- 当前 `parsing.onnx`（6.75MB）、`landmark.onnx`（4.7MB）在真实人脸上 mask / landmark 质量极差。
- 即便修好 #A 并走模型路径，多区域皮肤会错乱、瘦脸/大眼会变形错位——**不可用**。

**修复方向：** 采集 ≥5K 自有/合规标注（皮肤 6 类 + 106 点），训练并导出 ONNX，再正式启用模型路径。
（合规硬约束：禁第三方预训练 / 商业 SDK；公开集仅作冷启动 seed，不进成品分布。）

### #C【中】「多区域遮罩（脸/脖/臂）」UI 标签与实际算法不符

- UI 文案暗示语义分割，但默认路径是**单区域阈値法**（一幅连通皮肤），不具备 face/neck/arm 语义区分。
- 会误导用户以为生成的是精准分部位遮罩。

### #D【低】美体完全缺失，Tab 命名误导

- `types.ts:123` 明确「不做美体」；无 body keypoint / body warp / 相关 UI / 导出逻辑。
- 与 Tab 名「美颜美体」冲突。

### #E【信息】工程正确性良好（值得肯定）

- **导出侧美颜链路正确**：`build_beauty_spec`(bilateral 磨皮 / eq 美白 / unsharp 清晰 / lutrgb 肤色) +
  `alphamerge + overlay` 合成（**绝不用 `maskedmerge`**，已规避全局泄漏，见 `graph.rs:434-436`）。
- **关键帧**：`beauty.smoothing/whitening/clarity` 支持时间分段烘焙（#6 同款机制），逐帧生效。
- **warp 形变**：`warp.py` 数学设计严谨（瘦脸向鼻轴高斯收拢、大眼径向 raised-cosine 放大），
  `gray16le` 绝对坐标 + 恒等不变性已实现并验证；导出 `remap` 与预览 `applyWarp` 契约一致。
- **CUDA EP 注入**（`_prepend_cuda_dll_path`）正确，ONNX 推理可 GPU 加速。

## 3. 战备结论

- **立即可战备**（仅需小修 #A）：阈値法皮肤磨皮 / 美白 / 清晰 / 肤色（适用**单人主脸、背景非同色**场景）。
- **需模型训练才可战备**：多区域精分割美颜(P1)、瘦脸 / 大眼(P2)。
- **未开发**：美体、美妆、匀肤 / 祛斑 / 黑眼圈。

## 4. 建议优先级

1. **修 #A（契约 bug）**——小改动、高收益，让基础美颜皮肤立即可用。
2. **采集并训练 ≥5K 标注** → 启用 P1 多区域 + P2 关键点（解锁精分割与瘦脸大眼）。
3. **收敛命名**——「美颜美体」改「美颜（皮肤/塑形）」或标注美体未开发；修正 #C 标签。
4. （如需）**规划美体全新模块**（body keypoint + body warp + UI）。
