## 关键架构决策
- **SR 不是 ffmpeg 滤镜**（需 onnxruntime CUDA EP 逐帧推理）→ 不进 `graph.rs` 滤镜链
- **SR = 导出级后处理**：渲染临时视频 → Python 超分 → 最终输出
- 前端 SRTab 只做"生成 + 独立对比预览"，**不进 WebGPU 时间轴合成**（分辨率不同，架构不允许）

## 最近决策（2026-08-05，鲲鹏定稿）

### 1. 场景分类定稿为 6 类（采纳 DeepSeek 建议）
- **人像 / 风景 / UI / 老电影 / 低光 / 高速运动**，对应 `python/sr/dataset.py` 的 `SCENE_CATEGORIES`。
- **城市建筑(urban) 的几何直线/强边缘纹理价值单独保留**：不并入 6 类，但训练扫描时仍纳入
  （`dataset.PRESERVED_SCENES = ("urban",)`），作为与 UI 硬边缘互补的几何线条来源。
- 代码已落地：`dataset.py` 常量更新 + `__init__` 始终补入 preserved 场景。

### 2. 数据"扩量"按实际需求走（第一性原理）
- DeepSeek 高估了"数量级"（建议 2000~3000 段）；其"扩量+补低光/运动+硬负例"三件事中，
  **扩量部分不盲目跟随**——达到超清目的即可，不必堆量。
- 关键前提已就位：**合成退化工厂（`degradation.py` 二阶退化+块丢失+振铃，每 epoch 重随机参数）
  使 1 段原视频在训练中 ≈ 多种退化变体**，这比纯堆原始素材高效得多。
- 当前数据：portrait=150、landscape=137、urban=7、text_ui=6；old_film/low_light/high_motion 暂为空
  （按用户指示暂停采集，不强行扩充）。

### 3. 第一要务是修训练 NaN（非继续堆数据）—— 已实现
原来 g_loss 在 ~200 iter 先涨后 NaN，根因：**判别器过早压制生成器 + 无梯度裁剪/无 GAN 预热 → 梯度爆炸污染权重**。
`python/sr/train.py` 已修复：
- **梯度裁剪**：G/D 各自 `clip_grad_norm_`（默认 1.0），scaler.unscale 后裁剪；
- **GAN 预热+升温**：`gan_warmup_iters=2000` 内只做 L1+MS-SSIM，`gan_ramp_iters=8000` 内 w_gan 0→目标线性升温；
- **NaN 防护**：d_loss/g_loss 非有限则跳过该步更新，避免污染权重；
- **判别器 R1 正则**（`r1_weight=10`，可关）稳定对抗；
- **PATH 自清洗**：`import torch` 前剥离 PATH/CUDA_PATH 中的 NVIDIA/CUDA 冲突项，规避 Windows 上系统
  CUDA v12.8 与 torch 自带 CUDA 12.8 的 DLL 冲突段错误（已实测是环境冲突源之一）。
- 新增崩溃重试启动器 `scripts/run_sr_train.bat`（torch import 偶发段错误时自动重试）。

### 关键决策

1. **12块 vs 23块**：23块需 batch=2（OOM 风险），训练 4× 慢（3.3天），画质收益递减。12块是帕累托最优。
2. **batch=6/8 vs 4**：batch=6 刚好卡满 16GB 边界，GPU 利用率已 98%，无实质加速。
