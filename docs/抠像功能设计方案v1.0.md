## 1. 背景与目标

抠像（Keying）是把视频中指定颜色区域（绿幕/蓝幕）或主体（人像）变成透明，使素材可叠加到其他背景上。目标分三档能力：

- **P0 色度抠图（Chroma Key）**：绿幕/蓝幕等纯色背景去除，算法经典、无专利风险，作为首版交付。
- **P1 智能抠像（Smart Key / Matting）**：AI 自动分离人像/主体与背景，输出软边 alpha。
- **P2 手动抠像（Manual）**：画笔涂抹前景/背景辅助修正，延后实现。

## 2. 专利与协议规避策略

| 方案 | 协议 | 决定 |
|------|------|------|
| 自研 HSV/颜色距离色度键 | 公有领域算法 | ✅ P0 采用 |
| RVM (Robust Video Matting) | **GPL-3.0（强 copyleft）** | ❌ 规避，不用 |
| MODNet | **Apache-2.0** | ✅ P1 候选，商用友好 |
| RMBG-2.0 (BRIA) | **MIT** | ✅ P1 备选，更轻量 |
| ONNX Runtime | **MIT** | ✅ 推理运行时 |

- 色度抠图使用经典颜色键 + 溢出抑制（spill suppression）+ 边缘柔化，均为业界通用公有技术，不依赖任何受专利保护的专有流程。
- 智能抠图仅集成 Apache-2.0 / MIT 权重与运行时，不引入 GPL 代码，避免对闭源桌面端造成协议传染。
- 推理流程（帧提取 → ONNX 推理 → alpha matte 合成）为自研管线，模型权重作为可下载资源按需获取（HF 镜像 `hf-mirror.com`）。

## 3. 总体架构

```
                ┌─────────────── ClipConfig.keying: Option<KeyingConfig> ───────────────┐
                │  非破坏式字段，默认值关闭，不影响未启用片段                          │
                └────────────────────────────────────────────────────────────────────┘
                                   │
        ┌──────────────────────────┴──────────────────────────┐
   预览（实时）                                              导出（离线）
   PreviewCanvas → composeMaskedFrame                        Rust graph.rs → ffmpeg
   ├ WebGPU 多 pass（主路径，navigator.gpu）                  ├ P0: filters.rs 生成 colorkey/chromakey 滤镜串
   └ HTML5 Canvas 回退（CSS mask / 逐帧 2D）                  └ P1: alpha PNG 序列 + 原视频合成（或 vf 滤镜）
```

- 复用蒙版模块的「非破坏式字段 + 预览合成 + 导出挂载」三层模式（详见调研结论）。
- 同一 `KeyingConfig` JSON 契约前后端共享：前端 `types.ts` 与后端 `types.rs` 字段名逐字一致（serde 对齐）。

## 4. 数据模型（前后端共享契约）

```ts
// 前端 gui/src/types.ts
type KeyingMode = 'chroma' | 'smart' | 'manual';

interface KeyingConfig {
  enabled: boolean;
  mode: KeyingMode;
  // —— P0 色度抠图参数 ——
  color: string;        // 键色，hex，如 '#00ff00'，支持吸管取色
  similarity: number;   // 0..1 颜色容差（越大抠得越多）
  edgeSoftness: number; // 0..1 边缘柔化（半透明过渡带宽度）
  spill: number;        // 0..1 溢出抑制强度（去除前景上的绿/蓝边）
  // —— P1 智能抠图参数（M1 不填） ——
  model?: 'modnet' | 'rmbg2';
  threshold?: number;   // alpha 二值化阈值
}
// ClipConfig 增加：keying?: KeyingConfig
```

```rust
// 后端 src/types.rs
#[derive(Serialize, Deserialize, Clone, Debug)]
#[serde(tag = "mode", rename_all = "lowercase")]
pub enum Keying {
    Chroma { color: String, similarity: f32, edge_softness: f32, spill: f32 },
    Smart  { model: String, threshold: f32 },
    Manual { /* 延后 */ },
}
// Clip 增加：pub keying: Option<Keying>
```

## 5. P0 色度抠图（M1 实现）

### 5.1 算法（前端预览 + 后端导出一致）
1. **颜色键**：把每像素与键色在 RGB/HSV 空间比较，距离 < `similarity` 判定为背景→alpha=0。
2. **边缘柔化**：距离在 `[similarity, similarity+edgeSoftness]` 区间线性过渡 alpha（半透明抗锯齿带），对标蒙版羽化的各向同性处理，避免硬边。
3. **溢出抑制**：对保留的前景像素，沿键色反方向减绿/减蓝（despill），消除前景边缘的绿边伪影。

### 5.2 前端预览
- 在 `maskRender.ts` 的 `composeMaskedFrame` 同位置增加 `applyChromaKey(frameCanvas, clip.keying)`：HTML5 路径用 `getImageData` 逐像素（`similarity`/`edgeSoftness`/`spill` 一致公式）；WebGPU 路径用等价 WGSL 片元着色器。
- 性能：预览按显示分辨率处理，非原分辨率。

### 5.3 前端 UI（KeyingTab）
- 新增 `KeyingTab` 面板，挂入与 `MaskTab` 相同的 Inspector 位置。
- 控件：启用开关、**吸管取色**（从视频帧取键色）、相似度滑块、边缘柔化滑块、溢出抑制滑块。
- 写回走 live 系（拖动不打快照）+ 拖前 `pushHistorySnapshot()`，与蒙版滑块一致。

### 5.4 后端导出（Rust）
- `filters.rs::build_keying_spec`：生成 ffmpeg 滤镜段。
  - 主滤镜：`colorkey=color=0x00ff00:similarity=S:blend=E`（RGB 色键，blend 即边缘柔化）。
  - 溢出抑制：叠加 `chromakey` 或 `colorhold`/`format` 组合（按实测选定），或自研 `geq` 表达式。
- `graph.rs`：在对应视频流挂 keying 滤镜；带 alpha 的输出需在 scale/map 处保留 `format=rgba`，最终封装为支持透明的容器（或导出 alpha PNG 序列后合成）。

## 6. P1 智能抠图（M2-M3，待 M1 验收后启动）

- **模型**：MODNet (Apache-2.0) 权重转 ONNX，ONNX Runtime (MIT) 推理；备选 RMBG-2.0 (MIT)。
- **管线（自研）**：抽帧（按 fps 或关键帧）→ 缩放至模型输入 → ONNX 推理得 alpha matte → 与原始帧合成 RGBA。
- **预览**：首帧/抽帧推理结果缓存为 alpha 遮罩，预览时叠加（实时逐帧推理由按钮触发，非自动）。
- **导出**：推理整段得 alpha PNG 序列，Rust 用 ffmpeg 以 `alphamerge`/序列帧合成最终透明视频；或直接走 ONNX 推理子进程产出中间素材再合成。
- **UI**：模型选择、触发推理按钮、推理进度/状态；可选阈值滑块。
- **资源获取**：HF 镜像 `HF_ENDPOINT=https://hf-mirror.com` 按需下载权重，首次使用提示下载。

## 9. 待确认决策（开发前已按推荐选定，记录备查）

1. **智能模型选型**：优先 MODNet（人像 matting 成熟）；若体积/速度不达标，切 RMBG-2.0。→ 按推荐先 MODNet。
2. **推理触发方式**：手动按钮触发（非自动），避免大视频卡顿。→ 已定。
3. **导出透明视频容器**：优先 ffmpeg `alphamerge` + 支持 alpha 的封装（webm/qt rgba）；若本机 ffmpeg 不支持，回退 alpha PNG 序列。→ 实现时按本机能力实测选定（参照蒙版 text 导出三坑的实测风格）。
4. **色度键 ffmpeg 滤镜**：`colorkey`（RGB）为主，溢出抑制按实测选 `chromakey` 或自研 `geq`。→ 实现时实测。

## 10. 风险与对策
- 本机 ffmpeg 滤镜能力差异（如蒙版 text 导出的坑）→ 每个滤镜链先用 `render` 子命令实跑验证。
- 智能模型权重体积大 → 按需下载 + 进度提示，不随安装包内置。
- 预览与导出不一致 → 前端公式与后端 ffmpeg 参数映射逐字节对齐，建对照表单测。
