## 一、火山引擎智能美化特效 SDK（剪映底层能力来源）

### 1.1 SDK 概况

剪映的底层能力来自字节跳动的**火山引擎智能美化特效 SDK**（简称 CV SDK / Effect SDK）。

| 维度 | 信息 |
|------|------|
| 官方入口 | https://www.volcengine.com/docs/6705/1535830 |
| SDK 名称 | 智能美化特效 SDK（Effect SDK） |
| 最新版本 | 4.8.1（2026-05-13） |
| 支持平台 | Android / iOS / Windows / HarmonyOS |
| 授权模式 | 付费授权（License + 技术支持），需联系商务获取 Maven 凭证 |
| 核心能力 | 美颜、美妆、滤镜、贴纸、2D/3D 特效、背景分割、手势识别 |

### 1.2 公开 API 能力清单

| 能力 | API 接口 | 说明 |
|------|---------|------|
| 基础美颜 | `enableEffectBeauty` / `setBeautyIntensity` | 美白(默认0.7)、磨皮(0.8)、锐化(0.5)、清晰(0.7) |
| 高级特效 | `setComposerNodes` / `updateComposerNode` | 美颜+美形+美体+美妆+滤镜任意叠加 |
| 贴纸道具 | `setEffect(path)` | 2D/3D 贴纸，上万款抖音同款 |
| 人脸检测 | FaceDetectTask | 200+ 自研视觉算法 |
| 手势识别 | HandDetectTask | 手势触发特效 |
| 骨骼检测 | SkeletonTask / Skeleton3DTask | 人体追踪 |
| 3D 人脸 | FaceFitting3DTask | 3D 面部拟合 |
| 人脸比对 | FaceVerifyTask | 身份验证 |

### 1.3 资源包结构

```
ComposeMakeup.bundle/     # 美颜+美妆素材
  ├── beauty_4Items       # 4项基础美颜
  ├── beauty_IOS_lite     # 轻量美颜
  └── reshape_lite        # 微整形
FilterResource.bundle/    # 滤镜素材
StickerResource.bundle/   # 贴纸道具包
ModelResource.bundle/     # AI 模型资源
LicenseBag.bundle/        # 授权证书
```

### 1.4 对 AIcut 的启示

- **CV SDK 是付费闭源**，AIcut 无法直接使用，但可参考其能力分层和资源包格式
- **资源包结构**对 R3 特效热更新设计有直接参考价值（bundle 化、composer nodes 组合）
- **AI 能力**（人脸/手势/骨骼检测）可作为后续 AIcut 的云 API 调用方向
- **接入成本高**：需要商务洽谈 + License + Maven 私有仓库凭证，不适合开源项目

## 二、开源视频编辑器项目调研

### 2.1 ⭐ OpenCut（最重要参考）

| 维度 | 信息 |
|------|------|
| GitHub | https://github.com/BunsDev/OpenCut |
| Stars | 72,669+（2025年6月创建，一年内爆发增长） |
| 许可证 | MIT |
| 定位 | 开源 CapCut/剪映 替代品，隐私优先（全本地处理） |
| 技术栈 | **Rust 核心** + TypeScript/Next.js 前端 + WASM 绑定 |
| 桌面端 | GPUI（Zed 编辑器的 Rust UI 框架） |
| 核心特性 | 多轨道时间轴、实时预览、无水印、MCP Server、无头模式、插件架构 |

**架构对比（OpenCut vs AIcut）**：

| 层 | OpenCut | AIcut（当前） | AIcut（目标） |
|----|---------|-------------|-------------|
| 渲染核心 | Rust（GPU 合成/特效/蒙版） | Rust（FFmpeg 命令构建） | Rust（GPU 合成 + FFmpeg 导出） |
| 前端 | Next.js + React | **不存在** | 待建（参考 OpenCut） |
| 桥接 | WASM 绑定 | N-API（条件编译） | N-API / WASM 双模式 |
| AI 集成 | MCP Server | MCP 骨架（mcp.rs） | 完善 MCP |
| 无头渲染 | `--headless render` | CLI 二进制 | 增强 CLI |
| 桌面端 | GPUI | **不存在** | Electron / GPUI 选型 |
| 插件系统 | 规划中（沙箱隔离） | **不存在** | 参考 R3/R4 设计 |

**可借鉴点**：
1. **Rust 核心 + WASM 绑定**：OpenCut 把 Rust 编译为 WASM 在浏览器运行，AIcut 可借鉴实现 Web 端
2. **MCP Server 设计**：OpenCut 是首个内置 MCP 的视频编辑器，AIcut 的 mcp.rs 可对标其 API 设计
3. **无头模式**：`opencut --headless render --input ... --output ... --parallel 4`，AIcut 的 CLI 可增强为类似模式
4. **插件优先架构**：第三方特效/转场/滤镜作为一等公民，沙箱隔离——与 R3/R4 设计方向一致
5. **脚本标签页**：直接在编辑器中写 JS/TS 自动化任务，AIcut 可考虑

**注意事项**：
- OpenCut 正在大规模重写，导出功能和预览面板标记为"避免贡献"（正在重构）
- 桌面端（GPUI）仍在开发中，Web 版最成熟
- AIcut 不应直接 fork OpenCut（不同目标：AIcut 侧重 AI 能力 + 中国生态），但应深入研究其 Rust 核心设计

## 三、节拍检测 / 自动卡点算法选型

### 3.1 方案对比

| 库 | 语言 | 模式 | 精度 | 延迟 | 集成难度 | 推荐场景 |
|----|------|------|------|------|---------|---------|
| **madmom** | Python | 离线 | ⭐⭐⭐⭐⭐ 最高 | - | 中（需 Python 子进程） | 离线分析、批量处理 |
| **BeatNet** | Python | 实时+离线 | ⭐⭐⭐⭐ 高 | <50ms | 中（需 Python 子进程） | 实时节拍同步 |
| **librosa** | Python | 离线 | ⭐⭐⭐ 中 | - | 低 | 轻量级 tempo 估算 |
| **aubio** | C/Python | 实时+离线 | ⭐⭐⭐⭐ 高 | 低 | 低（C 绑定 Rust） | 嵌入式、实时 |
| **beat-detector** | Rust | 实时 | ⭐⭐ 中低 | 0.05ms | **最低（原生 Rust）** | 实时预览卡点 |
| **realtime-bpm-analyzer** | TypeScript | 实时 | ⭐⭐⭐ 中 | 中 | 低（npm 直接用） | Web 端实时检测 |

### 3.2 AIcut 推荐方案

**分层策略**（精度与性能兼顾）：

```
┌─────────────────────────────────────────┐
│  实时预览卡点（低延迟优先）               │
│  → beat-detector (Rust 原生，0.05ms/帧)  │
│  → 或 realtime-bpm-analyzer (Web 端)     │
├─────────────────────────────────────────┤
│  导出时精确卡点（精度优先）               │
│  → madmom (Python 子进程，RNN 最精确)     │
│  → 通过 MCP 工具 transcribe_beats 调用   │
├─────────────────────────────────────────┤
│  轻量级 tempo 估算（快速预览）            │
│  → librosa 或 aubio（C 绑定）             │
└─────────────────────────────────────────┘
```

**集成路径**：
1. **MVP**：用 `beat-detector`（Rust 原生 crate）实现基础节拍检测，零外部依赖
2. **增强**：通过 MCP 工具调用 `madmom`（Python 子进程）做精确离线分析
3. **Web 端**：用 `realtime-bpm-analyzer`（TypeScript）做浏览器实时检测

## 四、智能抠像技术选型

| 方案 | 类型 | 说明 | 集成方式 |
|------|------|------|---------|
| **RobustVideoMatting** | 开源模型 | PyTorch，实时人像抠像，质量高 | Python 子进程 / ONNX Runtime |

## 七、关键结论

1. **OpenCut 是 AIcut 最重要的对标项目**——架构几乎一致（Rust+TS+MCP），72K stars 验证了技术路线可行性。应深入研究其 Rust 核心设计，但不直接 fork（AIcut 侧重点不同）

2. **火山引擎 CV SDK 是付费闭源**——AIcut 无法直接使用，但其能力分层和资源包格式（bundle 化、composer nodes 组合）对 R3 特效热更新设计有直接参考价值

3. **节拍检测优先用 Rust 原生方案**——`beat-detector` crate 零外部依赖、0.05ms/帧，满足实时预览需求；精确分析通过 MCP 调用 `madmom`

4. **AI 能力走"开源模型 + 云 API"双路线**——基础能力用开源模型（MediaPipe/Whisper/RobustVideoMatting），高端能力按需调用云 API（火山引擎/豆包），避免重度依赖付费 SDK

5. **AIcut 的差异化方向**——OpenCut 强调隐私（全本地），AIcut 可强调 AI 能力（智能卡点/抠像/字幕/文案/TTS），两者形成互补
