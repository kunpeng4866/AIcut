# AIcut 多轨道渲染管线架构设计

> 调研依据：`deepseek剪映资料复刻.txt` 第二个问答（数据层 / 渲染调度层 / 执行处理层三层架构）
> 现状依据：`CLAUDE.md` + `src/graph.rs` + `src/project.rs` + `src/ffmpeg.rs` + `docs/AIcut设计方案_Phase5_草案.md`
> 目标：把当前"单次 FFmpeg 命令构建"升级为可实时调度、可降级、可并行的多轨道渲染管线，并与 Phase 5 WebGPU 预览衔接。

---

## 0. 背景与目标

### 0.1 现状诊断

| 维度 | 现状 | 问题 |
|---|---|---|
| 渲染入口 | `graph.rs:94 build_render_command` 把整条时间线编进一条 `-filter_complex` 字符串 | 不可流式、不可中断、不可并行；超长工程会触发 FFmpeg 表达式上限 |
| 预览 | TS 侧 `extractFrame`（FFmpeg 抽单帧 PNG） | 每帧 0.2s+，无连续播放；无降级机制 |
| 数据访问 | `Project::tracks[i].clips[j]` 线性扫描 | 每帧查询 O(轨道数 × 片段数)，30fps × 10 分钟视频 = 1.8 万次扫描 |
| 解码 | FFmpeg 单进程内部解码 | 没有跨帧复用、没有预解码、没有硬解优先策略 |
| 音频 | 与视频同 filter_graph | 无法独立调优延迟、无限制器 |

### 0.2 设计目标

1. **导出管线（高质量）**：零丢帧、最佳画质、可并行解码，替代当前单次命令
2. **预览管线（低延迟）**：高帧率、允许降级跳帧、与 Phase 5 WebGPU 合成器复用
3. **统一数据层**：`给定 T → 所有轨道激活片段` 的 O(log n) 查询，导出/预览共享
4. **同源模型**：预览所见 = 导出所得（同一 Project + 同一 TimelineIndex + 同一变换/特效语义）

### 0.3 设计原则

- **Rust 主导调度**：数据层 / 调度层 / 解码 / CPU 合成在 Rust；TS 负责 UI + WebGPU 合成器（Phase 5 复用）
- **薄接口、厚内核**：N-API 只暴露 `build_timeline / query / render_tick`，复杂逻辑全在 Rust
- **渐进式**：先跑通"查询→解码→合成→编码"单轨道骨架，再补并行/缓存/降级
- **单次命令保留**：`graph.rs` 不删，作为"快速导出"快速路径继续可用

## 2. 数据层：时间线模型（`src/timeline.rs`）

### 2.1 问题定义

渲染管线每帧都要回答：

> 给定时间点 T（秒），返回所有轨道在 T 时刻的有效片段，按轨道层级排序。

- 频率：30fps × 10 分钟 = 18000 次查询
- 必须做到 O(log n)，不能 O(n×m) 全量扫描

### 2.2 Rust crate 选型调研

| crate | 维护 | 特性 | 是否适用 |
|---|---|---|---|
| `rangemap` | 活跃（700+ stars） | `RangeMap<K,V>`，点查询 O(log n)，支持重叠区间 | ✅ 主选 |
| `btree-range-map` | 活跃 | 严格 BTreeMap 区间映射 | 可选 |
| `interval_tree` | 低活跃 | 通用区间树 | 过重 |
| `std::collections::BTreeMap` | 标准库 | 按 key 排序，需手动处理 end 边界 | ✅ 零依赖备选 |

**关键观察**：编辑器侧 `Track.clips` 在用户编辑时天然按 `timeline_in` 递增（插入新片段会保持有序），所以**主索引直接用 `Vec<ClipRef>` + 二分查找**就够，无需引第三方 crate。

**最终决策**：
- **主路径**：自建轻量索引 `Vec<ClipRef>` + `binary_search by timeline_in`，零依赖
- **重叠场景**：转场叠加时两个 clip 在 [t_out - xfade_dur, t_out) 区间共存，索引不特殊处理，由 `ActiveSlice.active_transitions` 单独描述
- **可选升级**：若未来支持自由重叠片段（非转场场景），引 `rangemap` 即可，接口不变

### 2.4 查询接口

```rust
impl TimelineIndex {
    /// 从 Project 构建（O(N)，N=所有片段数）
    pub fn build(project: &Project) -> Self {
        let mut tracks: Vec<TrackIndex> = project.tracks.iter()
            .map(index_track).collect();
        // 按 order 排序，保证 query_at 返回顺序确定
        tracks.sort_by_key(|t| t.order);
        let duration = project.total_duration();
        let fps = project.canvas.fps;
        let total_frames = (duration * fps as f64).ceil() as u64;
        Self { tracks, duration, fps, total_frames }
    }

    /// 点查询：T 时刻所有激活片段
    /// 复杂度：O(tracks × log(clips_per_track))
    pub fn query_at(&self, t: f64) -> ActiveSlice {
        let mut slice = ActiveSlice {
            time: t,
            video_clips: vec![],
            audio_clips: vec![],
            text_clips: vec![],
            active_transitions: vec![],
        };
        for track in &self.tracks {
            if let Some(idx) = binary_search_active(&track.clips, t) {
                let cref = &track.clips[idx];
                let ac = ActiveClip {
                    track_id: track.track_id.clone(),
                    clip_id: cref.clip_id.clone(),
                    asset_id: cref.asset_id.clone(),
                    track_order: track.order,
                    local_time: compute_local_time(t, cref),
                    progress: (t - cref.timeline_in)
                              / (cref.timeline_out - cref.timeline_in).max(1e-6),
                };
                match track.track_type {
                    TrackType::Video => slice.video_clips.push(ac),
                    TrackType::Audio => slice.audio_clips.push(ac),
                    TrackType::Text  => slice.text_clips.push(ac),
                    TrackType::Effect => {}, // 特效轨依附视频轨，不在主切片
                }
            }
        }
        // 转场探测（在 query_at 内顺便处理）
        slice.active_transitions = detect_transitions(&self.tracks, t);
        slice
    }

    /// 范围查询：[t0, t1) 内所有片段（预解码窗口用）
    pub fn query_range(&self, t0: f64, t1: f64) -> Vec<ActiveSlice> { /* ... */ }

    pub fn frame_to_time(&self, frame: u64) -> f64 {
        frame as f64 / self.fps as f64
    }
    pub fn total_frames(&self) -> u64 { self.total_frames }
    pub fn duration(&self) -> f64 { self.duration }
}

/// 在按 timeline_in 排序的 Vec 中二分查找覆盖 t 的片段
fn binary_search_active(clips: &[ClipRef], t: f64) -> Option<usize> {
    use std::cmp::Ordering::*;
    let idx = clips.binary_search_by(|c| {
        if t < c.timeline_in { Greater }
        else if t >= c.timeline_out { Less }
        else { Equal }
    }).ok()?;
    Some(idx)
}
```

### 2.5 local_time 计算（关键细节）

`graph.rs:14` 的 `build_speed_curve_expr` 是把曲线变速编码为 FFmpeg 表达式（正向）。渲染管线在 CPU 侧查询需要**反向**：已知播放时间 `play_t`，求源素材时间 `src_t`。

```rust
/// 给定时间点 t 和片段引用，计算该片段在 T 时刻应解码的源素材时间
fn compute_local_time(t: f64, cref: &ClipRef, clip: &Clip) -> f64 {
    let play_t = t - cref.timeline_in;          // 片段已播放时长
    if clip.speed_curve.is_empty() {
        // 线性速度
        clip.src_range.start + play_t * clip.speed
    } else {
        // 曲线变速：在 SpeedPoint 表上反查
        // SpeedPoint { src: 源时间, play: 播放时间 }
        invert_speed_curve(&clip.speed_curve, play_t) + clip.src_range.start
    }
}

/// 二分查找 play_t 所在的分段，线性反插值得到 src_t
fn invert_speed_curve(points: &[SpeedPoint], play_t: f64) -> f64 {
    if points.len() < 2 { return play_t; }
    // 找到 play_t 落在 [points[i].play, points[i+1].play) 区间
    let idx = points.windows(2)
        .position(|w| w[0].play <= play_t && play_t < w[1].play)
        .unwrap_or(points.len() - 2);
    let p0 = &points[idx];
    let p1 = &points[idx + 1];
    let dp = p1.play - p0.play;
    let ds = p1.src - p0.src;
    if dp.abs() < 1e-6 { return p0.src; }
    let ratio = (play_t - p0.play) / dp;
    p0.src + ratio * ds
}
```

**单测要求**：`invert_speed_curve` 与 `build_speed_curve_expr` 必须互逆（容差 1ms）。

### 2.6 与 project.rs 的衔接

- **`Project` 保持源真**：JSON 反序列化的产物，不增字段
- **`TimelineIndex` 是只读派生**：工程变更 → 重建 index（10 轨道 ×100 片段 ≈ 1ms，可忽略）

### 3.2 高质量导出管线（ExportPipeline）

```
┌──────────────────────────────────────────────────────────────┐
│  for frame_idx in 0..total_frames:                          │
│    t = frame_idx / fps                                       │
│    ① slice = timeline.query_at(t)               [O(log n)]  │
│    ② frames = parallel_decode(slice, t)         [rayon]     │
│    ③ composed = compositor.stack(slice, frames) [CPU]       │
│    ④ audio_chunk = audio_mixer.mix(t, block)                │
│    ⑤ encoder.write_video(composed)                          │
│    ⑥ encoder.write_audio(audio_chunk)                       │
│    clock.tick()  [Stepped: 解码完成才推进]                   │
└──────────────────────────────────────────────────────────────┘
```

**步骤详解**：

**① 查询**：`TimelineIndex::query_at(t)` → `ActiveSlice`

**② 并行解码**：用 `rayon::scope` 把每个 video clip 的解码任务分发到线程池

```rust
fn parallel_decode(
    slice: &ActiveSlice,
    pool: &DecoderPool,
    t: f64,
) -> Result<FrameBundle> {
    let frames: Vec<(ClipId, DecodedFrame)> = slice.video_clips
        .par_iter()
        .map(|ac| pool.decode_at(&ac.asset_id, ac.local_time).map(|f| (ac.clip_id.clone(), f)))
        .collect::<Result<_>>()?;
    Ok(FrameBundle::from(frames))
}
```

**③ 同步合成**：单线程按 display_order 逐轨道叠加（GPU 合成需共享上下文，不能并行；CPU 合成可考虑后续 SIMD 加速）

**④ 音频独立管线**（见 §4.3）

**⑤ 编码写入**：用 FFmpeg 进程管道模式（`-f rawvideo -i -` 喂 stdin，stdout 取编码后流）。`ffmpeg.rs` 需补充 `build_pipe_encoder` 接口。

**Stepped Clock 特点**：解码慢则整条流水线等，**绝对不丢帧**。

### 3.3 低延迟预览管线（PreviewPipeline）

```
┌──────────────────────────────────────────────────────────────┐
│  render_loop (rAF / 定时器, 目标 30fps):                     │
│    t = clock.now()                                          │
│    ① slice = timeline.query_at(t)               [O(log n)]  │
│    ② frames = decoder_cache.try_get(slice)      [非阻塞]    │
│       未命中 → 复用上一帧 / 黑场                            │
│    ③ 通过 N-API 把 frames 句柄传给 TS                       │
│    ④ TS 侧 PreviewEngine.WebGPU 合成（Phase 5 复用）        │
│    ⑤ 后台预解码线程: 预取 [t, t+0.5s) 的帧                  │
│    clock.tick()  [Realtime: 跟随 wall clock, 跳帧补偿]      │
└──────────────────────────────────────────────────────────────┘
```

**关键降级策略**：

| 策略 | 触发条件 | 行为 |
|---|---|---|
| 跳帧 | 单帧合成 > 33ms | clock 直接跳到 wall clock 对应帧号 |
| 降分辨率 | 预览源已是 720p proxy | 默认即降级，无需运行时判断 |
| 跳过复杂特效 | 特效 manifest 的 `gpu_tier == "heavy"` | 预览时跳过，导出时启用 |
| 复用上一帧 | `decoder_cache.try_get` 返回 `None` | 显示上一帧，绝不阻塞 |
| 跳过音频块 | 音频管线延迟超阈值 | 静音 + 标记 UI |

### 3.4 渲染时钟（`src/clock.rs`）

```rust
pub enum ClockMode {
    /// 实时：跟随 wall clock，预览用
    Realtime { start: Instant, last_tick: Instant },
    /// 步进：按帧推进，导出用
    Stepped { current_frame: u64 },
}

pub struct RenderClock {
    fps: u32,
    frame_duration: Duration,   // 33.3ms @30fps
    mode: ClockMode,
}

pub enum TickResult {
    Render(f64),           // 当前应渲染的时间点 t
    Wait(Duration),        // 距下一帧还需等待
    Done,
}

impl RenderClock {
    pub fn current_time(&self) -> f64 {
        match &self.mode {
            ClockMode::Realtime { start, .. } => start.elapsed().as_secs_f64(),
            ClockMode::Stepped { current_frame } => *current_frame as f64 / self.fps as f64,
        }
    }

    pub fn tick(&mut self) -> TickResult {
        match &mut self.mode {
            ClockMode::Realtime { last_tick, .. } => {
                let next = *last_tick + self.frame_duration;
                let now = Instant::now();
                if now >= next {
                    *last_tick = now;  // 重置基准，避免漂移
                    TickResult::Render(self.current_time())
                } else {
                    TickResult::Wait(next - now)
                }
            }
            ClockMode::Stepped { current_frame } => {
                *current_frame += 1;
                TickResult::Render(*current_frame as f64 / self.fps as f64)
            }
        }
    }
}
```

**同步策略**：
- **导出**：`Stepped`，每帧严格按 `frame_idx` 推进，解码/合成完成后才 tick，零丢帧
- **预览**：`Realtime`，rAF 驱动；解码慢于播放节奏时跳到当前 wall clock 对应帧号（保持音画同步）

```rust
    /// LRU，key = (asset_id, frame_idx)
    map: lru::LruCache<(String, u64), DecodedFrame>,
    /// 容量：默认 300 帧（约 10s @30fps，1080p YUV420 ≈ 300×3MB = 900MB）
    /// 预览模式降到 150 帧（720p ≈ 150×1MB = 150MB）
    capacity: usize,
}

pub enum HwAccel { Cuda, D3D11va, Qsv, Software }
```

**硬解优先策略**：
- 启动时执行 `ffmpeg -hwaccels`，探测可用硬件加速器
- H.264/H.265 用 `h264_cuvid` / `hevc_cuvid`（NVIDIA）或 `d3d11va`（Windows 通用）
- 失败回退软解（`libx264` 软编对应 `h264` 软解）

**实现路径（两阶段）**：
- **阶段 1（推荐起步）**：用 FFmpeg subprocess 抽单帧（`ffmpeg -ss <t> -i <input> -frames:v 1 -f rawvideo -`），延迟 50–100ms，但零 FFI 复杂度
- **阶段 2（性能优化）**：用 `ffmpeg-next` crate（libavcodec Rust binding）做内存内解码，延迟 5–10ms

**预解码窗口**（后台预取线程）：

```rust
impl DecoderPool {
    /// 后台线程循环：预取播放头前 0.5s 的帧
    pub fn prefetch_loop(&self, timeline: &TimelineIndex, playhead: Arc<AtomicF64>) {
        loop {
            let t = playhead.load();
            let future_slice = timeline.query_range(t, t + 0.5);
            for ac in future_slice.iter().flat_map(|s| &s.video_clips) {
                let key = (ac.asset_id.clone(), frame_idx(ac.local_time, timeline.fps));
                if !self.cache.read().contains(&key) {
                    let pool = self.clone();
                    self.pool.spawn(move || {
                        if let Ok(frame) = pool.decode_at(&ac.asset_id, ac.local_time) {
                            pool.cache.write().put(key, frame);
                        }
                    });
                }
            }
            std::thread::sleep(Duration::from_millis(50));
        }
    }
}
```

**逐轨道合成流程**（对齐 deepseek 资料"从下至上"）：

```rust
impl Compositor for CpuCompositor {
    fn composite(&mut self, slice: &ActiveSlice, frames: &FrameBundle, project: &Project)
        -> Result<CompositedFrame>
    {
        let mut canvas = Frame::black(self.width, self.height);

        // 按 track_order 升序：order 小的下层，大的上层
        for ac in &slice.video_clips {
            let clip = project.find_clip(&ac.track_id, &ac.clip_id)?;
            let src = frames.get(&ac.clip_id)?;

            // 1. 应用变换（缩放/旋转/位移）
            let t = sample_transform(clip, ac.time);
            let transformed = apply_transform(src, &t, self.width, self.height);

            // 2. 应用不透明度（含关键帧 + 淡入淡出）
            let opacity = sample_keyframe(clip, "transform.opacity", ac.time, clip.transform.opacity);
            let opacity = apply_fade(opacity, clip, ac.time);

            // 3. 应用遮罩
            let masked = apply_masks(transformed, &clip.masks);

            // 4. 应用滤镜（色彩/模糊等）
            let filtered = apply_filters(masked, &clip.filters, ac.time);

            // 5. Over 合成（Porter-Duff Alpha 混合）
            canvas = over_composite(canvas, filtered, opacity);
        }

        // 转场处理：xfade 混合相邻片段
        for tr in &slice.active_transitions {
            apply_transition(&mut canvas, tr, frames);
        }

        Ok(CompositedFrame(canvas))
    }
}
```

### 4.3 音频独立管线（`src/audio.rs`）

```rust
pub struct AudioPipeline {
    decoders: HashMap<AssetId, Box<dyn AudioDecoder>>,
    sample_rate: u32,         // 来自 canvas.sample_rate，默认 48000
    channels: u16,            // 2（立体声）
    block_size: usize,        // 约 10ms = 480 samples @48kHz
    limiter: BrickwallLimiter,
}

impl AudioPipeline {
    pub fn render_chunk(&mut self, slice: &ActiveSlice, project: &Project, samples: usize)
        -> Result<AudioChunk>
    {
        let mut mix = AudioChunk::silence(self.sample_rate, self.channels, samples);

        for ac in &slice.audio_clips {
            let clip = project.find_clip(&ac.track_id, &ac.clip_id)?;
            // 1. 解码 + 重采样到统一格式
            let raw = self.decoders[&ac.asset_id].decode_block(ac.local_time, samples)?;
            let resampled = resample(raw, self.sample_rate);

            // 2. 应用音量 + 关键帧 + 淡入淡出
            let vol = sample_keyframe(clip, "volume", ac.time, clip.volume);
            let gained = apply_volume(resampled, vol);
            let faded = apply_fade(gained, clip, ac.time);

            // 3. 应用音频特效（denoise / equalizer）
            let effected = apply_audio_filters(faded, &clip.filters);

            // 4. 多路混音（累加）
            mix = mix_add(mix, effected);
        }

        // 5. 限制器（防止爆音）
        Ok(self.limiter.process(mix))
    }
}
```

**Rust crate 选型**：
- **重采样**：`rubato`（纯 Rust，高质量 Sinc/Linear）
- **EQ 滤波**：`biquad` crate（标准二阶节）
- **限制器**：自研 brickwall（lookahead 5ms + soft clip）
- **混音**：自研 SIMD 加法（`std::simd` 或 `wide` crate）

**节奏来源**：声卡时钟驱动（不是视频时钟）。预览模式下音频块请求频率约 100Hz（10ms/块），独立于视频 30Hz。

## 5. 与 Phase 5 WebGPU 预览的衔接

### 5.1 分工调整

| 层 | Phase 5 草案方案 | 本设计调整 |
|---|---|---|
| Timeline 逻辑 | TS 纯函数 `Timeline.ts`（`activeVideoLayers` / `activeTransition` / `activeTextSubtitle`） | **改为 N-API 调 Rust `TimelineIndex`**，TS 仅薄桥接 |
| 解码 | `<video>` 标签硬解 + `requestVideoFrameCallback` | 保持不变；Rust 侧 `DecoderPool` 仅服务导出管线 |
| 合成 | WebGPU WGSL 着色器（TS） | 预览复用；导出用 `CpuCompositor` |
| 缓存 | 浏览器 `<video>` 自带 | 预览靠浏览器；导出用 Rust `FrameCache` |

### 5.2 关键决策：Timeline 逻辑统一到 Rust

**理由**：导出和预览必须同源，否则"所见即所得"只能靠人肉对齐。Phase 5 草案在 TS 写 Timeline 纯函数，与 Rust 导出引擎的 `graph.rs` 逻辑（如 `build_speed_curve_expr` 的转场 offset 计算）平行存在，长期会漂移。

**调整方案**：
- **Rust 侧**：`TimelineIndex::query_at` 作为单一真相源
- **TS 侧**：`packages/ui/src/preview/timelineBridge.ts` 调 `napi_export_query(handle, t)`，返回扁平 `ActiveSliceDto`
- **代价**：每次查询一次 N-API 调用（实测 < 0.05ms，30fps 下完全可接受）

### 5.3 代理 720p 复用

`ffmpeg.rs:201` 已有 `build_proxy_command` + `generate_proxies_batch`，本设计直接复用：

- **预览管线**：TS 侧 `<video src="aicut-asset://<id>?proxy=1">` 加载 720p proxy
- **导出管线**：Rust 侧 `DecoderPool` 用**原始素材 path**（不降级）
- **代理生成时机**：素材导入时自动触发（`needs_proxy(width, height)` 返回 true 时）

### 5.4 "预览所见 = 导出所得"一致性保证

| 一致性维度 | 实现方式 |
|---|---|
| 同一 Project 模型 | TS 和 Rust 共享同一份 JSON schema（`project.rs` ↔ `project.ts`） |
| 同一 Timeline 查询 | TS 调 Rust `napi_export_query`（单一真相源） |
| 同一变换语义 | Rust `apply_transform` 与 WGSL `effects.wgsl.ts` 顶点着色器共用同一矩阵公式；单测互校 |
| 同一关键帧采样 | Rust `sample_keyframe` 与 TS `KeyframeTrack.sample` 同算法，单测覆盖相同输入 |
| 同一滤镜参数 | Rust `build_filter_spec` 与 WGSL 片元着色器参数表共享（一份 JSON 配置） |
| 同一转场公式 | `xfade=offset=...:duration=...` 的 offset 计算（`graph.rs:169`）在 Rust `detect_transitions` 中复现 |

**单测策略**：对每个变换/特效，构造参考 Project，分别在 `CpuCompositor` 和 WGSL 渲染同一帧，像素级对比（容差 < 1/255）。

## 8. 风险与待验证项

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| FFmpeg subprocess 解码延迟过高（50–100ms/帧） | 导出慢、预览无法实时 | 阶段2 升级到 `ffmpeg-next` FFI（5–10ms/帧） |
| WebGPU 在 Windows 旧机型不可用 | 预览无法 GPU 加速 | Phase 5 已有 `extractFrame` 回退；2D canvas 中间档 |
| Rust→TS 帧传输开销 | 预览卡顿 | 用 `SharedArrayBuffer` 或 N-API `Buffer` 零拷贝；后续探索 GPU buffer 直接映射 |
| 曲线变速反查精度 | 音画不同步 | `invert_speed_curve` 单测覆盖 + 容差 < 1ms |
| 音频块边界对齐 | 爆音 | 块间 overlap-add，淡入淡出处理 |
| 多轨道 4K 预览内存爆 | OOM | 预览强制 720p proxy；`FrameCache` 容量按分辨率动态调整 |
| FFmpeg 滤镜探测不准 | 降级失效 | `ffmpeg.rs:149 probe_filters` 已有，保留；管线模式下 CPU 合成不依赖滤镜可用性 |
| 硬解器跨平台差异 | NVENC 不可用 | `HW_ENCODERS` 表已含 AMF/QSV fallback；运行时探测 |

## 9. 关键决策摘要

1. **不引 `rangemap`**：编辑器侧已保证 clips 有序，`Vec + binary_search` 足够；未来需要自由重叠再引
2. **Timeline 逻辑统一到 Rust**：替代 Phase 5 草案的 TS 纯函数方案，避免双份实现漂移
3. **导出用 CPU 合成，预览用 WebGPU 合成**：导出稳定优先，预览延迟优先；共用同一份变换/特效语义
4. **解码分两阶段**：subprocess 起步，`ffmpeg-next` FFI 优化
5. **音频独立管线**：声卡时钟驱动，10ms 块，与视频时钟解耦
6. **保留 `graph.rs`**：作为"命令行快速导出"路径，与管线模式共存
7. **`Stepped` vs `Realtime` 时钟**：导出零丢帧，预览可跳帧，策略模式切换
