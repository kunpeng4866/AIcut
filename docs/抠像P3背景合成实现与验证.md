## 1. 目标

P3 在 P1/P2 得到的**已抠像 RGBA（前景 + 透明背景）** 基础上，增加**背景替换 / 合成**能力：

- 抠像后留下的透明区域，可被三类背景填入：
  - **纯色**（solid color）；
  - **图片**（image，静态铺满铺满）；
  - **视频**（video，循环垫底，与源素材同步播放进度）；
  - **无**（none，保持透明，默认）。
- 预览（WebGPU + HTML5 双路径）与导出（ffmpeg graph）**都生效**。
- 设计原则：背景合成**只发生在抠像之后**，复用既有"已抠像 RGBA"产物，不改动 matte 生成链路；
  因此导出只新增一段 `overlay` 滤镜，预览只新增 `compositeBackground` 垫底函数。

## 2. 架构（预览 / 导出两套合成，共用 KeyingConfig.background）

```
KeyingConfig.background = { type:'none'|'color'|'image'|'video', color?, assetId? }
        │
        ├─ 预览（两路都调 keyingRender.compositeBackground 垫底）
        │    ├─ WebGPUPreview.tsx：getBackgroundFrame() 取 color/image/video 帧
        │    │     → compositeBackground(keyedCanvas, bg, vw, vh) → 上传纹理
        │    └─ PreviewCanvas.tsx：KeyedCanvas.applyBackground() 同逻辑（HTML5 canvas）
        │
        └─ 导出（src/graph.rs build_video_chain 在 matte 之后插入 overlay）
             ├─ color  → color=c=0xRRGGBB:s=WxH:r=FPS 作底
             ├─ image  → [bgId:v]scale=W:H 作底
             └─ video  → [bgId:v]scale=W:H 作底（与源同步循环由 overlay shortest=1 + 源时长决定）
             overlay=shortest=1 把底垫到 [pre_tail]（已抠像 RGBA）之下
```

关键：预览双路径都调用 `keyingRender.ts` 的 `applyKeying/applyMatte` → 把背景合成加在 `keyingRender` 层，
**两路自动生效**，无需在两条预览分支各写一遍。

## 4. 实现要点

### 4.1 预览层 `gui/src/utils/keyingRender.ts` —— `compositeBackground(keyed, bg, vw, vh)`
- `bg` 为颜色串（`#rrggbb`）→ `ctx.fillStyle=bg; ctx.fillRect(0,0,vw,vh)` 垫底，**再** `drawImage(keyed)` 叠前景。
- `bg` 为 `CanvasImageSource`（图片 / 视频当前帧）→ 先 `drawImage(bg,0,0,vw,vh)` 垫底，再叠 keyed。
- `bg` 为 `null` → 直接返回 keyed（保持透明）。
- 先垫底后叠前景，保证抠除的透明区被背景填满、前景不变。

### 4.2 WebGPUPreview.tsx
- import `compositeBackground`。
- 新增 `bgImageCacheRef` / `bgVideoCacheRef` 与 `getBackgroundFrame(keying, srcTime, srcPaused, srcRate, vw, vh)`：
  - `color` → 返回颜色串；
  - `image` → 按 `assetId` 取素材路径，`new Image()` 缓存，返回该 Image；
  - `video` → 按 `assetId` 取素材，`new HTMLVideoElement()` 缓存，设 `currentTime = srcTime % duration`
    （与源同步、取模循环），返回该 video。
- 抠像块之后、上传纹理之前：若 `clip.keying.enabled && clip.keying.background && uploadSource instanceof HTMLCanvasElement`
  → 调 `compositeBackground(uploadSource, bg, vw, vh)` 垫底后再 `copyExternalImageToTexture`。

### 4.3 PreviewCanvas.tsx（HTML5 回退 + DOM 叠加）
- import `compositeBackground`；`KeyedCanvas` 组件签名新增 `assets: AssetConfig[]` prop（替代 projectRef）。
- 新增 `bgVideoRef` / `bgImageRef` 与 `applyBackground(keyed, vw, vh)`（同 4.2 三型，video 与源同步 currentTime）；
  组件卸载时 `pause()` + 解绑背景 video/image 元素，避免泄漏。
- 调用点 `<KeyedCanvas ... assets={project.assets} />`。
- 两分支（isMatte / else chroma）`drawImage` 前先 `applyBackground(keyed, vw, vh)`。

### 4.4 导出层 `src/graph.rs` —— `build_video_chain(c, idx, w, h, label, fps, matte_map, bg_map)`
- 签名新增 `bg_map: &HashMap<String, usize>`（背景 assetId → 输入索引）；`build_clip_chain` / 三处调用点同步传 `&bg_map`。
- 在 matte 块之后、tail 之前插入背景 overlay：
  ```rust
  if let Some(k) = c.keying.as_ref() {
    if k.enabled {
      if let Some(bg) = k.background.as_ref() {
        if bg.bg_type != "none" {
          let bg_label = format!("{}bg", label);
          match bg.bg_type.as_str() {
            "color" => {
              let hex = bg.color.trim_start_matches('#');
              nodes.push(format!("color=c=0x{}:s={}x{}:r={}[{}]", hex, w, h, fps, bg_label));
              nodes.push(format!("[{bg_label}][{pre_tail}]overlay=shortest=1[{bgout}]"));
            }
            "image" | "video" => {
              if let Some(bi) = bg.asset_id.as_ref().and_then(|id| bg_map.get(id).copied()) {
                nodes.push(format!("[{bi}:v]scale={w}:{h}[{bg_label}]"));
                nodes.push(format!("[{bg_label}][{pre_tail}]overlay=shortest=1[{bgout}]"));
              }
            }
            _ => {}
          }
        }
      }
    }
  }
  ```
- `build_render_command` 新增 `bg_map` 收集：image / video 背景的 `assetId` 命中 `assets` → 追加 `-i`（第二输入）。
- > ⚠️ **铁律（两坑已修）**：
  > 1. **`overlay=format=rgba` 是无效选项** —— 本机 ffmpeg 报 `Error applying option 'format' ... Invalid argument`，
  >    导出 `-22`。改为裸 `overlay=shortest=1`。
  > 2. **`color=c=...` 是无限长源** —— overlay 不加 `shortest=1` 会一直等待导致 ffmpeg 卡死（3~4 分钟无输出）。
  >    所有背景 overlay 一律 `shortest=1`：垫底源（color/image/video）以源 clip 时长为准结束。

### 4.5 UI `gui/src/components/panels/KeyingTab.tsx`

## 6. 已知限制 / 后续
1. **无音轨源导出崩溃（pre-existing，非 P3 专属）**：`graph.rs` 对 video 轨音频无条件引用 `[0:a]`，
   源无音轨则 ffmpeg 报 `-22`。验证时用带音轨源（`test_video_audio.mp4`）绕过；建议后续按 `ffprobe` 探测有音轨再挂音频链。
2. **桌面端须彻底重启生效**：改动横跨渲染层（vite build）与 Rust 引擎（cargo build），**两次构建产物都须重建，
   且须彻底重启 AIcut 桌面端**（`isDev` 恒 false，renderer 改动需 `vite build` + 彻底重启；引擎需 `--release` 或重编译 dev）。
3. **视频背景循环以源 clip 时长为界**：overlay `shortest=1` 取较短者（源 clip 时长），背景视频长于源则被截断、
   短于源则循环（由 ffmpeg 对第二输入循环填充）。如需严格"无限循环铺底"可后续改 `loop=1`。
4. **图片背景为静态单帧铺满**：按 `scale=W:H` 拉伸铺满，未做 cover/contain 适配；后续可加 `force_original_aspect_ratio`。
