# AIcut 分发安装包现状与建议（2026-08-22）

> 目的：搞清楚「用户下载一份安装包、解压即用的 AIcut」到底由哪些东西组成、现在缺什么。
> 结论先行：**git 仓库的 224MB ≠ 用户下载的产品**。AIcut 目前被事实上「拆成两部分」——代码在 git，运行时（ffmpeg / Python / AI 模型）全在仓库外、靠本机路径或首次运行下载。上一份报告里「干净交付 = 32MB 字体 + <5MB 源码」是**对仓库体积的误读，不是产品体积**，此处正式更正。

---

## 一、git 工作树是否完整？（是否漏了已开发但没提交的内容）

**结论：源码完整，没有遗漏。**

- `git status --short` 干净，无 stash，无游离的 `??` 真源码（`docs/` 报告是我本次新写的）。
- 894 个文件 / 约 224MB 是**完整的源码 + 测试权重 + 字体 + 死重 vendor**，已开发且需保留的内容都已入库。
- `target/release/aicut-engine.exe`（2.27MB，8-16 构建）在磁盘存在但被 gitignore——这是正确的（二进制不进 git，打包时由 `extraResources` 从 `target/release` 取）。

⚠️ 一处需决策：仓库里的 `python/models/sr_v0_test.onnx`（约 120MB，LFS）是**随机测试权重**（真实权重未到位），并非成品模型，且占 LFS 配额。建议正式发布前从 git 移除（保留本地副本即可）。

---

## 二、运行时依赖与模型到底在哪？（你问的「rmbg2 几百兆」真相）

AIcut 跑起来需要的「非源码」部分，全部**不在 git 仓库内、且当前都没打包**：

| 组件 | 本机实际位置 | 是否在 git | 打包配置是否含 | 终端用户如何获得 |
|---|---|---|---|---|
| **Rust 引擎** `aicut-engine.exe` | `target/release/`（2.27MB） | ❌ gitignore | ✅ `extraResources→engine/` | 打包内置 |
| **ffmpeg** | `/e/codex/codex-tools/bin/ffmpeg.exe`（本机，**项目外**） | ❌ | ❌ **未打包** | 目前靠 PATH，用户需自备 → **必须捆绑** |
| **Electron 运行时** | `gui/node_modules/electron` | ❌ gitignore（npm install） | ✅ builder 自动 | 打包内置 |
| **中文字体** `public/fonts` | 项目内（32MB，LFS） | ✅ LFS 指针 | ✅ `extraResources→fonts` | 打包内置 |
| **Python 解释器** | **硬编码** `C:\Users\Administrator\.workbuddy\binaries\python\envs\default\Scripts\python.exe`（开发者本机） | ❌ | ❌ **未打包** | 用户机器**绝对不存在此路径** → 致命 |
| **AI 模型（MODNet/rmbg2/语音/SR）** | 首次运行下载到 `~/.cache/aicut/models/` | ❌ | ❌ | 运行时联网下载（HF 镜像 / ModelScope / GitHub） |

**关于你提到的「rmbg2 就几百兆」——属实且确认：**

- `python/keying/core.py`：`RMBG2_MODEL_FILENAME = "rmbg2.onnx"`，注释写明 **FP32 权重约 976MB**（BiRefNet 架构，Apache-2.0），从 ModelScope 国内镜像首次下载缓存。
- MODNet：`modnet.onnx`（Xenova/HF 或 ZHKKKe GitHub Release，约数十 MB）。
- 口播剪辑（Demucs + faster-whisper + silero-vad）：需对应 Python 包 + 模型（whisper 每语种约 150MB、Demucs 约 100MB）。
- 超清 SR：`model_g` ONNX（真权重未到位，目前随机权重骨架）。

**关键代码事实（已核实）：**
- 引擎 `src/ffmpeg.rs` 用 `Command::new("ffmpeg")` —— **假设 ffmpeg 在 PATH**，没有指向捆绑路径的逻辑。
- `gui/electron/main.ts:25` 把 Python 解释器**写死成开发者机器上的 WorkBuddy venv 路径**，且无任何「相对路径/可配置」回退。这是分发包的**致命 blocker**：任何非开发者机器上 AI 功能（抠像/口播/超清）一启动就找不到 python。
- 模型缓存在 `os.path.expanduser("~/.cache/aicut/models")`，纯运行时下载，无预置、无进度强约束（有日志回调但缺失网失败兜底）。

## 三、224MB 真的就是全部吗？（澄清上一份报告的误导）

**不是。** 概念混淆更正：

- **224MB = git 仓库快照**（代码 + 测试权重 + 字体 + 死重 vendor）。这是「你 push 到 GitHub 的东西」，不是「用户下载的东西」。
- **用户真正下载的产品** = 仓库源码（打包后极小）+ 运行时（ffmpeg / Python / 模型）。这些运行时**根本不在 224MB 里**。
- 上一份说「干净交付 ~32MB 字体 + <5MB 源码」是指**瘦身后的仓库体积**，被误读成产品体积，特此更正。

### 假设现在做安装包，体量估算

**精简版（仅基础剪辑：裁剪/变速/转场/旋转/翻转/导出，不含 AI）：**
- Electron 运行时（builder 内置）~ 60–80MB
- 引擎 `aicut-engine.exe` ~ 2.3MB
- ffmpeg（**需新增捆绑**）~ 70–90MB
- 字体（LFS）~ 32MB
- **合计 ≈ 170–200MB**。无需 Python、无需下载模型，离线可用。

**完整版（含全部 AI：抠像/rmbg2/口播/超清/ASR）：**
- 上述精简版 ≈ 200MB
- Python 环境（捆绑 embed 版 + 依赖，或引导用户装）~ 400–700MB
- 模型（首次下载 or 预置）：MODNet ~30MB + **rmbg2 ~976MB** + 口播 ~300MB + SR ~35MB ≈ **1.3GB**
- **合计 ≈ 1.5–2.3GB**（若模型改为首次运行下载，安装包可压回 ~200MB + 首跑联网拉模型）。

> 你提的「精简版/完整版」思路完全成立，且天然对应上表：精简版不含 Python+模型，完整版含。差异就是那 ~1.5GB 的 AI 运行时，可按需选装/首跑下载。

## 四、做安装包前必须修复的 blocker（先不动手，仅列）

1. **【致命】Python 解释器路径硬编码**（`main.ts:25`）
   写死开发者机器路径，用户机器必崩。需改为：优先 `process.resourcesPath/python/...`（捆绑）+ env 覆盖 + 找不到时引导安装。否则 AI 功能全废。

2. **【高】ffmpeg 未捆绑**
   `extraResources` 缺 ffmpeg；引擎只从 PATH 找。需把 ffmpeg 拷进 `resources/ffmpeg/`，启动前置 PATH 或改引擎指向捆绑路径。

3. **【高】`electron:build` 未验证跑通过**
   配置存在，但 `target/release` 引擎虽在、ffmpeg/Python 缺失会导致打包产物残缺。需先补齐 extraResources 再实跑一次。

4. **【中】模型获取策略未定**
   精简版不打包；完整版要决定「预置 vs 首跑下载」。当前是首跑下载，需补：下载进度 UI、失败兜底（断网提示）、可选预置路径。

5. **【中】Windows 专属路径冻结**
   `main.ts` 多处绝对 Windows 路径（WorkBuddy venv、`C:\Users\...`）。跨机/跨用户必失效，须全部改为相对 `resourcesPath` 或 env 注入。

6. **【低】仓库瘦身（非产品必需，但利于发布）**
   删除死重 `vendor/`（73MB，`.cargo/config.toml` 空、未被引用）+ 随机 SR 测试权重（120MB LFS）。仓库可降到 ~30MB 级。

---

## 五、给你的建议（决策层面）

1. **先修 blocker 再打包**：第 1、2 条不修，做出来的包用户一开 AI 功能就崩，基础剪辑也因缺 ffmpeg 无法导出。
2. **采用「精简版默认 + 完整版可选」双包策略**：与你设想一致。精简版离线可用、体积小、覆盖 80% 剪辑需求；完整版通过「捆绑 Python+模型」或「首跑下载」二选一提供 AI 能力。
3. **模型走「首跑下载 + 可选预置」**：避免安装包撑到 2GB+；rmbg2 这 976MB 让用户按需拉取更合理，完整版可提供一个「下载全部 AI 模型」的一键入口。
4. **Python 用 embed 版捆绑进 resources**，不要依赖系统/python 解释器，消除环境差异。
5. **正式发布前清理仓库**：删 vendor 死重 + 随机 SR 权重，仓库体积与健康度都受益。

> 以上均为「情况梳理 + 建议」，**未做任何代码改动**。需要动手时，建议从第 1、2 条 blocker 开始（这是分发包能否跑起来的前提）。
