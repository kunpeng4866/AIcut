## 一、P0 致命级（功能缺失 / 导出崩溃，用户直接可见）

### 1. 字幕 / 文字导出彻底丢失 ⭐最高优先级（**已修复** ✅，2026-08-09）
- **设计承诺**：`src/lib.rs:156-163` 注释"任何轨道含文字/字幕叠加层 → 走完整路径渲染 drawtext"；`docs/字幕字体调研报告.md` 整篇以"导出与预览字体一致"为前提。
- **代码实际（修复前）**：GUI 导出走 `render()` → `graph.rs`，但 `graph.rs` 全文无字幕 `drawtext` 烧录（仅 180/416 行的 `drawtext` 用于**文字蒙版**）。文字/字幕片段 `assetId='_text'/'_subtitle'`（前端哨兵值，无对应素材）在 `asset_to_idx` 查不到 → `continue` 静默跳过。`build_subtitle_overlay_filters` 唯一生产调用点是 `export.rs:405`（GUI 不可达）。
- **实测（修复前）**：含 text 轨 + subtitle 轨的工程跑 `render`，输出命令 `drawtext` 出现次数 = 0。
- **影响**：预览里能看到的所有标题字、SRT 字幕、AI 字幕，**导出成片后一个字都没有**。
- **修复（2026-08-09）**：`src/graph.rs` 引入 `resolve_clip_input()`：有真实素材 → `[idx:v]`；无素材但带 `text`/`subtitle`（哨兵 `assetId`）→ 合成透明黑底流 `color=c=black@0:s=WxH:d=D,format=rgba` 作为 drawtext 画布，overlay 时透出底层视频；否则才是 `None`（跳过孤立 sentinel clip）。并在 `build_video_chain` 的预抠像链注入 `subtitle::build_text_overlay_filter` / `build_subtitle_overlay_filters`（局部时间戳 `0..dur`，`enable='between(t,0,dur)'`）。单 clip 文字轨底色 `d=1e9`（近无限）以免 `overlay=shortest=1` 截断主时间线；多 clip 文字轨底色 `d=片段真实时长`。
- **验证（修复后）**：`cargo run -- render scripts/test_sentinel_subtitle.json`（哨兵 `_text`+`_subtitle` 双轨 + 背景视频轨）输出 filtergraph 含标题 `drawtext='…assetId=_text…':enable='between(t,0,5)'` 与两条字幕 `drawtext='第一条字幕'…between(t,1,3)`、`drawtext='第二条字幕'…between(t,3,5)'`，三层均经 `overlay` 烤进 `va3`。`cargo build` 通过。`scripts/test_subtitle_project.json`（真实素材 + text/subtitle）同样验证通过。详见第七节。

### 2. 蒙版文字标签硬编码冲突（真实逻辑缺陷，**已修复** ✅）
- **修正说明**：原审计称"前导逗号 → ffmpeg 直接失败"为**误读**——实际 `graph.rs:416-455` 文字蒙版语句用 `[bgT]drawtext...[tx0]`（无前导逗号），前导逗号顾虑不成立。真正存在的缺陷是下方标签冲突。
- **代码实际**：`src/filters.rs:586 build_text_mask` 对文字蒙版流**硬编码**标签 `[bgT]`/`[tx0]`（旋转分支再加 `[txraw]`）。`build_mask_spec`（`filters.rs:419-424`）遍历 clip 上所有 `shape=="text"` 蒙版，每个都生成相同标签的 `color=...[bgT];[bgT]drawtext...[tx0]` 语句。ffmpeg 允许标签在被消费后重定义，故同一 clip 多个文字蒙版时**不硬崩溃**，但后续 `alphamerge` 引用 `[tx0]` 只会取到**最后一个**文字蒙版流，前面的文字蒙版被静默丢弃 → 渲染结果错误（仅最后一个文字蒙版生效）。
- **实测**：构造两文字蒙版 filter_complex（旧标签重复）→ 解析通过但两次 alphamerge 等价引用同一 `[tx0]`，首蒙版丢失；新唯一标签（`bgT0/tx00`、`bgT1/tx01`）全接上 → 解析通过且各自正确。
- **影响**：同一片段叠加多个文字蒙版时，只有最后一个文字蒙版真正生效，其余被覆盖。非崩溃，但属真实逻辑缺陷。
- **修复（2026-08-09）**：`build_text_mask` 增 `idx: usize` 参数，标签改为 `bgT{idx}`/`txraw{idx}`/`tx0{idx}`，`im.label` 同步唯一化；`build_mask_spec` 传入文字蒙版序号。`cargo build` 通过，ffmpeg 验证通过（见第七节）。

### 3. 撤销 / 重做 off-by-one 永久性错乱（**已修复** ✅，2026-08-09）
- **代码实际**：`gui/src/store/historyStore.ts:34-45`。`future` 压入的是 `past[length-1]`（上一步）而非当前态；`undo()` 返回 `past[len-2]`（**多退一步**）；`redo()` 拿不回撤销前状态。全仓无 historyStore 单测。
- **推演**：S0→S1→S2 后 `undo()` 返回 S0（应为 S1），`redo()` 返回 S1（应为 S2）。
- **影响**：撤销一次跳两步；重做拿不回撤销前状态。高频操作，体验严重受损。
- **修复（2026-08-09）**：`undo(current)`/`redo(current)` 改为接收调用时刻的实时工程态（`projectStore.undo/redo` 传入 `get().project`）；`undo` 返回 `past[length-1]`（=应恢复态），`future` 压入 `current`；`redo` 返回 `future[0]`，`past` 压入 `current`。两步均单步往返正确。见第七节。

### 4. 锐化滤镜 → 整个导出崩溃（**已修复** ✅，且确认 GUI 可达）
- **可达性核实（2026-08-09）**：GUI 特效/滤镜面板（`EffectsPanel.tsx` + `PropertiesPanel.tsx:ItemsTab`）通过 `window.aicut.listPlugins()` **动态加载 `plugins/` 目录**的插件，点击即把 `kind: <插件id>` 追加到 `clip.filters`。`plugins/filter_sharpen/manifest.json` 的 `id="filter.sharpen"`、`name="锐化"` → 用户可在「调整(滤镜+特效)」面板选中并加到片段。导出时 `graph.rs:204 build_clip_filters` → `filters.rs:1037` 对注册的 `filter.sharpen` 调 `plugin_manager().build_filter` 生成 `unsharp=…`。**故锐化在 GUI 中真实可达**，非死代码。
- **代码实际**：`filter_spec` 原 `unsharp=5:5:{amount}:0:0`，第 4/5 位是 chroma 尺寸，合法区间 **3–23**，取 0 非法 → `chroma_msize_x out of range` → ffmpeg 退出。
- **实测**：`unsharp=5:5:0.5:0:0` 直接失败。
- **影响**：给任一片段加"锐化"再导出，ffmpeg 立即退出、`main.ts:536` 落盘错误，**整个导出失败**，报错与"锐化"无关联，极难自查。
- **修复（2026-08-09）**：`filter_spec` 改为命名形式 `unsharp=luma_msize_x=5:luma_msize_y=5:luma_amount={amount}:chroma_msize_x=3:chroma_msize_y=3:chroma_amount=0`（`amount` 默认 0.5、范围 0–2，替换后合法）。ffmpeg 实测 `amount=0.5`/`2` 均通过；manifest 运行时读取，无需重编 Rust。

## 二、P1 严重级（结果错误 / 与预览不符 / 性能）

### 5. 羽化转场 gblur 作用域泄漏 → 全片模糊（**已修复** ✅，2026-08-09）
- **代码实际（修复前）**：`src/graph.rs` `sigma=feather*0.25` 公式在，但 `gblur` **无 `enable='between(t,…)'` 时间门控**，且把模糊流赋回 `track_acc`，后续所有 `xfade/concat` 都以它为输入。
- **实测（修复前）**：3 片段 + wipe feather=10 → 第 3 段 concat 在 `[xb2]`（已 gblur）之后，全轨从该转场起全程模糊，且转场越多叠加越重。
- **影响**：用"线性擦除/圆形擦除"预设（默认 feather=10），成片从该转场起**永久失焦**；预览侧是精确边缘渐变遮罩，观感完全不同。
- **修复（2026-08-09）**：`src/graph.rs` feather 分支的 `gblur` 追加 `enable='between(t,offset,offset+xdur)'`，`offset=(prev.timeline_out - xdur) - master_origin`（=xfade 转场窗起点，相对 track_acc 累积时间轴），`xdur` 为夹到 `[0.1,5.0]` 的转场时长。仅转场窗内施加软边模糊，`enable=false` 时 gblur 透传原帧（保持清晰），故后续 xfade/concat 拿到的是清晰流，不再永久失焦。
- **验证（修复后）**：`cargo run -- render scripts/test_feather_transition.json`（3 片段 + wipe feather=10）输出 filtergraph：`[x2]gblur=sigma=2.50:enable='between(t,4,5)'[xb2]`、`[x3]gblur=sigma=2.50:enable='between(t,9,10)'[xb3]`，两处 gblur 均**仅限转场窗**，其余时段透传清晰。`cargo build` 通过。详见第七节。

### 6. 关键帧动画（transform / 旋转 / 透明度 / 音量）为空壳（**已修复** ✅，2026-08-09）
- **代码实际（修复前）**：
  - 后端插值数学 `src/keyframe.rs` 真实完整（含 9 单测），但**动画驱动层是假的**。
  - 快速路径 `graph.rs` `keyframed()` 对 transform/opacity 关键帧**只取整段时间中点一个值**采样 → 等于静态常数。
  - 前端 `KeyframesTab`（`KF_PROPS`）写入键 `x/y/scale/rotation/opacity/volume`（无 `transform.` 前缀；`scale` 为单一键同时驱动两轴），后端旧 `keyframed()` 查 `transform.x/transform.scaleX/transform.rotation/transform.opacity/transform.y` → **键名前缀 + scale→scaleX/Y 拆分均不匹配**，后端永远 get 不到 → 关键帧形同虚设。
  - 旋转 `src/compositor.rs:117` 为 `ExportPipeline`（GUI 不可达）路径的 TODO 空壳；**但 GUI 实际走 `graph.rs` 的 `rotate` 滤镜**，该路径此前仅因键名不匹配而失效。
- **修复（2026-08-09）**：`src/graph.rs`
  - 新增 `build_kf_expr(track, timeline_in)`：把关键帧轨道烘焙为 ffmpeg 时间表达式（局部 `t`）。以关键帧时刻为节点（线性段仅端点、表达式内本就线性插值；缓动段 8 等分细分采样 `sample()` 近似曲线），构造 `if(lt(t,p),v0+(v1-v0)*(t-p0)/(p1-p0),…)` 链；关键帧全局时刻统一减 `timeline_in` 对齐 clip 局部时间轴。
  - 新增 `kf_factor(clip, candidates, timeline_in)`：依次尝试候选键名（含前端键 `scale/rotation/opacity/x/y/volume` 与后端 `transform.*` 双前缀、`scale`↔`scaleX/scaleY`），命中即返回动画表达式，否则 `None`（回退静态值）。
  - 各属性接入：`scale` → `scale=w='trunc(expr*W/2)*2':h='…':eval=frame`；`rotation` → `rotate=a='expr*PI/180'`；`opacity` → `colorchannelmixer=aa='expr':eval=frame`；`x/y` → overlay `x='((expr)-0.5)*W'`/`y='(0.5-(expr))*H'`；`volume` → `volume='expr*track_vol':eval=frame`。
  - 同步修正 `keyframed()` 的键名兼容（双前缀 + scale 映射），作为静态回退。
- **验证（修复后）**：`cargo run -- render scripts/test_keyframe_animation.json`（单 clip，scale/rotation/opacity/x/y/volume 各 2 关键帧 0→5s）输出 filtergraph：`scale=w='trunc((if(lt(t,5),(0.5+(1.5-0.5)*(t-0)/5),1.5))*1280/2)*2'`（缩放 0.5→1.5）、`rotate=a='(if(lt(t,5),(0+(90-0)*(t-0)/5),90))*PI/180'`（0→90°）、`colorchannelmixer=aa='(if(lt(t,5),(0.2+(1-0.2)*(t-0)/5),1))':eval=frame`（0.2→1）、`overlay=x='((if(lt(t,5),(0+(1-0)*(t-0)/5),1))-0.5)*1280'`（位置 0→1）、`volume='(if(lt(t,5),(0+(1-0)*(t-0)/5),1))*1':eval=frame`（0→1）均**逐帧时间变化**。EaseOut 测试（`test_kf_eased.json` 临时）确认缓动段被 8 等分细分近似曲线。整条 filtergraph 长度仅 ~757 字符（优化前 0.1s 盲采约 25KB）。详见第七节。
- **影响（修复后）**：transform 类关键帧在 GUI 导出成片中与预览一致地真实动起来。`export.rs`/`compositor.rs` 的完整路径为 GUI 不可达的死代码，其关键帧空壳属结构性，不阻塞用户。

### 7. 闪光 / 故障特效导出与预览不一致
- **flash**：`effect_flash` manifest `eq=brightness='{intensity}*abs(sin(t*{speed}))'` 缺 `:eval=frame` → ffmpeg `eq` 默认 `eval=init` 只求值一次。实测导出恒定亮度（≈无效果），WebGPU 预览有脉冲、HTML5 回退是静态。
- **glitch**：`effect_glitch` `noise=alls={amount}`，`amount∈[0,1]` 而 ffmpeg `noise` 的 `alls` 是整数 0–100 → 被截 0，滑块拉满也只有 1。

### 8. 转场 easing / zoom / blur 参数导出被丢弃
- **代码实际**：`graph.rs:912 clip_transition_params` 返回 6 元组，但 `:809` 解构 `Some((_,_,_,feather,_,_))` **只消费 feather**。`zoom` 硬映射 dissolve、`blur` 映射 hblur 且 `blurAmount` 不参与、`easing` xfade 无该参数。这些字段注释自承"export.rs 逐帧路径消费"，而逐帧路径 GUI 不可达。
- **影响**：UI 选的缩放推进/模糊强度/缓动曲线在成片中静默失效，且调了没反应。

### 9. NVENC 硬件编码从未启用
- **代码实际**：`src/ffmpeg.rs:18-27 resolve_encoder` 实现完整，但**唯一调用方是测试**；`graph.rs:621-623` 只设分辨率/码率，`output_codec` 默认 `libx264`；`gui/electron/exportOptions.ts:125-136` codecMap 硬编码 libx264/libx265 并无条件覆盖 `-c:v`。
- **影响**：4K 导出全 CPU 软编，与"4K 强制硬件编码"设计承诺冲突。

### 10. 吸附阈值 0.5s 而非承诺的 0.05s
- **代码实际**：`gui/src/components/Timeline.tsx:40` `const SNAP_THRESHOLD_CLIP = 0.5;`（注释单位秒），两个吸附开关共用此粗阈值，无独立 0.05s 精细通道。
- **影响**：拖拽吸附过早，精细对齐（卡 0.05s 网格）无法实现，偏离设计精度 10 倍。

## 七、修复记录（2026-08-09）

### ✅ #1 字幕 / 文字导出彻底丢失（已修复）
- **根因（复核确认非误报）**：此前"疑似误报"的判读只看了 `export.rs`（确会烧录字幕），但 GUI 导出链路是 `export:start` → `callEngine('render', tmpProject)` → 引擎 `render` 子命令 → `graph.rs`，**根本不经过 `export_project`/`ExportPipeline`**。`graph.rs` 旧代码对 `assetId='_text'/'_subtitle'`（前端哨兵值、无对应素材）在 `asset_to_idx` 查不到即 `continue` 跳过，且全文无字幕 `drawtext` 烧录 —— 故预览可见字幕、导出成片一个字没有，是**真实 P0 缺陷，非审计误报**。
- **修复**：
  - `src/graph.rs` 新增 `resolve_clip_input(c, vci, asset_to_idx, w, h, nodes, base_dur) -> Option<String>`：① 有真实素材 → `[idx:v]`；② 无素材但含 `text`/`subtitle`（哨兵 assetId）→ 注入 `color=c=black@0:s=WxH:d=base_dur,format=rgba[vbN]` 透明底流作 drawtext 画布（overlay 透出底层视频）；③ 否则 `None`（孤立 sentinel clip 跳过）。
  - `build_video_chain` 预抠像链注入字幕：`if dur>0 { fontfile_dir=AICUT_FONTS_DIR; text→build_text_overlay_filter(t,0,dur,w,h,&ff); subtitle→build_subtitle_overlay_filters(s,0,w,h,&ff) }`，`enable='between(t,0,dur)'`（graph.rs 用局部时间戳）。
  - 单 clip 分支：`resolve_clip_input(c, vci, …, base_dur=1e9)`（近无限时长，避免 `overlay=shortest=1` 截断主时间线）；多 clip 分支：每段 `base_dur=(timeline_out-timeline_in).max(0.1)`。
- **验证**：`cargo build` 通过（仅预存 unused-variable 警告）；`cargo run -- render scripts/test_sentinel_subtitle.json`（`_text`+`_subtitle` 双轨哨兵 + 背景视频轨）输出 filtergraph 含三层 drawtext 且全部经 `overlay` 烤入 `va3`；`scripts/test_subtitle_project.json`（真实素材 + text/subtitle）同样 `drawtext` 出现 3 次且 EXIT=0。

### ✅ #5 羽化转场 gblur 作用域泄漏 → 全片模糊（已修复）
- **根因**：`src/graph.rs` xfade feather 分支把 `gblur` 直接接到 `merged`（xfade 输出）并赋回 `track_acc`，但 `gblur` **无 `enable` 时间门控**，故对 `merged` 整条流（含转场前/后所有帧）全程模糊；而 `track_acc` 又成为后续所有 `xfade/concat` 的输入，导致从该转场起整轨永久失焦，转场越多叠加越重。
- **修复**：feather 分支的 `gblur` 追加 `enable='between(t,offset,offset+xdur)'`，其中 `offset=(prev.timeline_out - xdur) - master_origin`（xfade 转场窗起点，相对 track_acc 累积时间轴），`xdur` 为夹到 `[0.1,5.0]` 的转场时长。`enable=false` 时 gblur 透传原帧 → 仅转场窗内软边、其余时段清晰，后续 xfade 拿到清晰流。
- **验证**：`cargo build` 通过；`cargo run -- render scripts/test_feather_transition.json`（3 片段 + wipe feather=10）输出 filtergraph 含 `[x2]gblur=sigma=2.50:enable='between(t,4,5)'[xb2]` 与 `[x3]gblur=sigma=2.50:enable='between(t,9,10)'[xb3]`，两处 gblur 均严格限定在各自转场窗（offset/offset+xdur），修复前为无 `enable` 的全程模糊。

### ✅ #6 关键帧动画空壳（已修复）
- **根因**：① 键名不匹配——前端 `KF_PROPS` 写 `x/y/scale/rotation/opacity/volume`（无 `transform.` 前缀，`scale` 单一键驱动两轴），后端 `keyframed()` 查 `transform.x/scaleX/…` 永远 get 不到；② 即便匹配，`keyframed()` 只取 clip 时间中点采样 → 静态常数。两因叠加，关键帧在导出中完全无效。
- **修复**：`src/graph.rs` 新增 `build_kf_expr(track, timeline_in)`（关键帧轨道→ffmpeg 时间表达式，关键帧时刻为节点、缓动段 8 等分细分近似曲线、全局时刻减 `timeline_in` 对齐 clip 局部 `t`）+ `kf_factor(clip, candidates, timeline_in)`（依次尝试前端/后端双前缀键名，含 `scale`↔`scaleX/scaleY`）。各属性接入时间表达式：`scale`→`eval=frame`、`rotate=a='expr*PI/180'`、`opacity`→`colorchannelmixer=aa='expr':eval=frame`、`x/y`→overlay 表达式、`volume`→`volume='expr*track_vol':eval=frame`。`keyframed()` 同步修正键名兼容作静态回退。
- **验证**：`cargo build` 通过；`cargo run -- render scripts/test_keyframe_animation.json`（单 clip 全属性 2 关键帧 0→5s）输出 filtergraph 中 scale/rotation/opacity/x/y/volume 全部为逐帧 `if(lt(t,…),…)` 时间表达式；EaseOut 测试确认缓动段被 8 等分细分。整条 filtergraph 仅 ~757 字符（优化前 0.1s 盲采约 25KB）。测试夹具 `scripts/test_keyframe_animation.json`。

### ✅ #3 撤销/重做 off-by-one 错乱（已修复）
- **根因**：`historyStore.ts` 旧 `undo/redo` 不接收当前态，`future` 误压 `past[length-1]`（上一步）而非实时态；`undo` 返回切片后 `past[len-2]`，导致一次撤销多退一步、重做拿不回撤销前状态。
- **修复**：
  - `gui/src/store/historyStore.ts`：`undo`/`redo` 签名改为 `(current: ProjectConfig)`，返回值与压栈修正——`undo` 返回 `past[length-1]`（应恢复态）、`future` 压入 `current`；`redo` 返回 `future[0]`、`past` 压入 `current`。
  - `gui/src/store/projectStore.ts`：`undo/redo` 调用处传入 `get().project`（当前实时态），其余调用方（Header/Timeline）经 `projectStore` 透传，无需改。
- **验证**：独立脚本复刻修复后算法，跑完整序列断言全部通过（undo#1→S1、redo#1→S2、连续 undo→S0、连续 redo→S2、新分支清空 future、空栈返回 null）；`npx tsc --noEmit -p tsconfig.json` 退出码 0，无类型错误。
